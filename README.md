## 2. 它本来有多封闭

拿到手时它只是一个会议终端：有网口、有 WiFi、有屏幕，但你什么都改不了。

| 常规入口 | 状态 |
|---|---|
| 开发者选项 | **厂商从设置里删了**，"连点 7 次版本号"无效 |
| USB 调试 | USB-A 是 **Host 口**，A-A 线接电脑物理上枚举不出来 |
| 刷机 | 签名墙，固件包不可改（见 `docs/01-硬件与系统/`） |
| 拆机 | 不做硬件改造是底线 |
| ADB / SSH | 端口根本没开 |

**唯一对用户开放、且可写的配置项：`设置 → 服务器地址`。**

这就是整条链的立足点。

## 3. 打通路径：一条链拿到 root

```
能改服务器地址
   ↓  把 cloud.<厂商>.com 改成我们自己的机器
设备把本机当成云端
   ↓  中间人拿到全部 API 明文
云端下发什么就装什么（厂商自带的静默安装通道）
   ↓  装上去的 App 拿到 system 级应用身份
用这个身份反过来打开 adbd
   ↓
adb root  →  uid=0(root)
```

**关键认知：不需要过签名校验、不需要刷机、不需要拆机。**
厂商自己设计了一套「云端下发 + 静默安装 + 桌面图标直链」的运营机制，
我们把它当成一条合法通道来用 —— 用它的设计，走它的路。

> 完整过程（含每一步的实际报错、时序、验证方法）：
> [`docs/00-总览/打通全过程.md`](docs/00-总览/打通全过程.md)

### 拿到 root 之后的两条命令

```bash
adb connect <设备IP>:5555
adb shell id
# uid=0(root) gid=0(root) context=u:r:su:s0
```

设备出厂即 `userdebug`，`adbd` 可直接以 root 启动；系统自带 setuid `su`，
`adb shell 'su -c id'` 直接回 `uid=0`。装机后所有改动都落在 `/data/local/tmp`，
**系统分区一个字节不动**。

## 4. 走通之后能做什么

这台机器被改造成了一个带屏语音终端。**15 个自研模块**：

| 模块 | 做什么 | 包名 | 实现要点 |
|---|---|---|---|
| **电视直播** | IPTV 直播 + HLS 代理 | `com.lm.tv` | 自建 HLS 代理解决 4.4 的 TLS/编码兼容 |
| **B 站** | 网页壳 + 移动端适配 | `com.lm.bili` | WebView 注入 + 硬件解码 |
| **抖音** | 原生实现 | `com.lm.douyin` | 绕开 App 的 x86/arm64 依赖，自写播放器 |
| **小智语音** | 唤醒 → ASR → 语义 → TTS 全链路 | `com.lm.xiaozhi` | 自建 WebSocket，三层保障（真判定/心跳/守护） |
| **看家** | 相机监看 + 人脸检测 + 抓拍 + 邮件 | `com.lm.guard` | 抢占 camera、低清预览、1080p 抓拍、手写 SMTP |
| **云台** | 步进电机控制 | `com.lm.motor` | 直接驱动 TC78S600FNG |
| **听歌** | 本地/在线音乐 | `com.lm.music` | AudioTrack + 媒体音量接管 |
| **投屏** | 无线扩展屏 | `com.lm.screen` | Android 端 + macOS 端（Swift）配套 |
| **电源键 Home** | 电源键回桌面守护 | `com.lm.gohome` | 补原厂广播发送者的缺 |
| **桌面守护** | 桌面进程保活 | — | 防原厂 Launcher 被系统回收 |
| **桌面收录器** | 图标库/布局写入 | `com.lm.deskadd` | 批量维护 14 套布局 |
| **文件夹** | 自研极简本地文件管理器 | `com.lm.files` | 替换原厂那个"假文件管理器"（MyFullScreenWebActivity），带触摸滑动翻页 |
| **时钟组件** | 桌面时钟卡片，**含农历**（「农历九月廿六」） | `com.xylink.timewidget` | 原版 TextClock 只随 `ACTION_TIME_TICK` 每分钟刷，显示不了秒 → 改成 Service + Handler 每秒 push RemoteViews |
| **天气组件** | 桌面天气卡片 | `com.nemo.weather` | 原厂天气壳取不到厂商云数据、整块空白，自己实现顶上 |

> ⛔ 本仓库只包含应用层与桌面层的模块；涉及硬件外设控制的实现未包含在内。

**桌面**：原厂 `vulture.app.home`（MarlinLauncher）保留，外挂自建图标库与布局表。
**为什么不直接换掉它**：它同时是电话图标 provider、呼吸灯状态机、`GOHOME` 广播发送者 ——
禁用会导致电话图标消失、环形灯常亮（只能恢复出厂）。
详见 [`docs/07-模块实现逻辑/14-环形灯与麦克风-根因.md`](docs/07-模块实现逻辑/14-环形灯与麦克风-根因.md)。

## 6. 关键技术发现索引

这些是这次改造里最有复用价值的部分，每条都指向详细文档。

### 系统与兼容

| 发现 | 结论 | 文档 |
|---|---|---|
| Android 4.4 没有 `MediaProjection` | 软件投屏无解（`screenrecord` 不支持 h264），只能上硬件 | `docs/00-总览/HANDOFF.md` |
| `su -c "cmd1; cmd2"` 会被拆错 | 一次只传一条命令 | `docs/00-总览/命令速查.md` |
| 改 `/system` 必须 `chcon` | 否则 SELinux 让文件"存在但读不到" | `docs/00-总览/命令速查.md` |
| `/system` 只有 786MB 只读 | 大应用装 `/data` | `docs/00-总览/命令速查.md` |
| 老 JDK/dex 工具链 | 不用 Gradle，手写 build 脚本更可控 | 各模块 `build_*.sh` |

### 音频（坑最多的一块）

| 发现 | 结论 | 文档 |
|---|---|---|
| HAL 忽略 MONO 请求 | 实际返回**双声道交错** `[L,R,L,R]`，是唤醒失败的真凶 | `docs/07-模块实现逻辑/07-小智App-实现逻辑.md` |
| 双 DMIC 是独立两路 | 相关系数 0.342，不是同一声源复制 | `docs/04-功能模块/语音控制-麦克风真相与接管方案.md` |
| 厂商 App 会把 ADC 音量从 202 压到 160 | `out_rms` 从 11000+ 掉到 1646 | 同上 |
| `speaker volume` 被驱动锁死 26 | 只能走 AudioTrack / 媒体音量 | 同上 |
| 原厂抢麦 | `vulture.app.home` 持有录音通道，需接管 | `docs/05-故障复盘/故障复盘-20261108-原厂抢麦根治与长聊隔离.md` |

## 7. 复现前置条件

这不是一个「clone 就 build」的项目 —— 它是对一台具体设备的改造记录。要复现，你需要：

1. **一台同型号设备**（T70L / `octopus_f1`）。硬件不同，引脚、分区、原厂包名都不一样。
2. **能访问设备的 `网络`**（网线最稳，WiFi 也行）。第一次需要能改它的「服务器地址」。
3. **一台开发机**（本项目在 macOS 上完成）+ 以下工具：
   - Android SDK build-tools（`aapt` / `dx` / `zipalign` / `apksigner`）
   - JDK 8 及以下（4.4 的 dx 不认高版本 class）
   - `adb`（`adb connect` 走 TCP，不需要 USB）
4. **自签名密钥**：仓库不含 `.jks`，各 `build_*.sh` 首次运行会自动生成（口令取 `KS_PASS`，默认 `android`）。
5. **第三方服务凭据需自己申请**：
   - 小智语音：`CLIENT_ID`（源码里是 `YOUR_XIAOZHI_CLIENT_ID` 占位）
   - 看家邮件：SMTP 服务器 + 授权码（App 内设置页填，不写死）
   - 小度：本项目只保留了架构分析，**凭据已全部隐去**，需自行申请

> 脚本里的 `$HOME/re-tools/platform-tools` 是我本机的 adb 路径，
> 换成你自己的 Android SDK `platform-tools` 即可。
