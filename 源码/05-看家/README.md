# 看家 · T70L 人脸检测抓拍推送

> 产物：`app/guard.apk`（45 KB，零第三方依赖）
> 源码：`app/src/com/lm/guard/`（4 个类，约 1200 行）
> 运行环境：中移 T70L，Android 4.4.4 / API19 / armv7 / 1G RAM / 1280×800

---

## 一、它做什么

不录像，只**待人**。

- 常驻待机，摄像头一直开着，每 0.8 秒做一次人脸检测
- 检测到人脸 → 抓一张 **1920×1080** 原图 → 存本地 → **邮件推到你手机**
- 同一个场景 60 秒内不重复报；人离开 45 秒以上再回来，算新事件
- 本地只保留最近 200 张（约 40MB），自动删旧的
- 8G 空间按"只存抓拍"算，够存两万多张 —— 这就是不录像的原因

**实测**：4 分钟长住，内存稳定 40MB 不涨，整机负载约 6.5%（1080p 预览 + 每秒检测）。

## 二、怎么用

1. 桌面第 2 页 → **看家**
2. 点 **开始看家**（第一次会检查邮箱配置）
3. 右侧窗口显示**最近一张抓拍**，左下角是"最近事件"
4. 想换邮箱/调灵敏度 → **设置**

**设置项**：

| 项 | 说明 |
|---|---|
| SMTP 服务器 / 端口 / SSL | QQ `smtp.qq.com` `465` 勾 SSL；163 `smtp.163.com` `465`；Gmail `smtp.gmail.com` `465` |
| 发件邮箱 | 你的邮箱完整地址 |
| 授权码 | **不是登录密码**。QQ：设置→账户→开启 SMTP→生成授权码（16 位） |
| 收件邮箱 | 可填同一个 |
| 报警冷却秒数 | 默认 60 |
| 灵敏度 | 默认 0.35，越小越灵敏（误报也多） |
| 亮屏回页 | 值守中按电源键亮屏时，自动切回本页（默认开） |

填完点 **保存并发测试邮件**，收到就是通了。

## 二·五、出门怎么用（息屏值守）

看家本来就是给"人不在家"用的，所以**屏幕必须能关**。

1. 点 **开始看家**，等状态环变绿、写"监控中"
2. 点 **息屏值守**（主按钮下面那个带电源符号的）
3. 屏幕会在 **3~6 秒**内自己黑掉，服务照跑

回家后**按一下电源键**，屏幕亮起会**自动回到这一页**，直接点"停止看家"。
不想被自动拉回来 → 设置里关掉"亮屏回页"。
只想回桌面不停值守 → 右上角 **返回桌面**。

### 实测数据（2026-11-06）

| 场景 | 检测频率 |
|---|---|
| 亮屏 | 约 0.6 次/秒 |
| 熄屏 | 约 0.8~1.3 次/秒（相机降帧，所以把跳帧间隔从 12 帧压到 3 帧补回来） |

熄屏 30 秒实测 40 次检测、屏幕全程保持关闭。**人进门 1 秒内就会被检测到。**

### 关屏是怎么做到的

普通应用没有 `DEVICE_POWER` 权限，按不了电源键。走的是和抢摄像头同一条 root 通道：

```
App 写 /sdcard/HomeGuard/.need_screenoff
   → cam_guard.sh（root，每 2 秒轮询）发现文件
   → 先确认 mScreenOn=true（已经黑了就不按，免得又点亮）
   → /system/bin/input keyevent 26
```

> 坑：脚本里别写 `$BB dumpsys power` —— busybox 没有 `dumpsys` 这个子命令，
> 会静默返回空、永远判成"已经黑了"，按键根本不发。要用系统的 `dumpsys`。
>
> 坑（最阴的一个）：**Toast 窗口带 `FLAG_KEEP_SCREEN_ON`**。点按钮时弹的提示还挂在
> 屏幕上，这期间按电源键是关不掉的 —— 表现为"点立即息屏有时管用、有时没反应"。
> 所以 App 里等 3.2 秒（Toast 消失）再写请求文件，`cam_guard.sh` 里再补一次
> "2 秒后还亮就重按"的兜底。
>
> 坑：`MainActivity` **不能**加 `FLAG_SHOW_WHEN_LOCKED` / `FLAG_DISMISS_KEYGUARD`，
> 实测会让刚关掉的屏幕立刻又亮起来（keyguard 重算时唤醒屏幕）。这台机器本来就没锁屏。
>
> 坑：改库/写库时 `database is locked` 很常见，脚本里必须带重试。

## 二·六、本地照片管理（二级页）

看家主界面右下角数据卡里的 **「本地照片」** 行（带"管理"字样和箭头），
点一下进相册；也可以直接点右侧**预览窗**那张大图。

- 4 列网格，每张显示抓拍时间 + 文件大小，新照片在最上
- 点照片 = 勾选/取消；右上角**全选 / 反选 / 删除选中**
- 删除会弹二次确认，显示要删几张、共多大
- **长按某张照片** = 打开大图预览（全屏原图）
- 缩略图用 `inSampleSize=4` + 8MB `LruCache`，上百张也不卡
- 删除同步写回看家的"最近事件"，主界面立即反映

**大图预览**：长按打开，支持

- 左右滑动切换上一张/下一张
- 双指缩放（1x~4x），放大后可拖动
- 右下角「删除」单张删除（自动切到下一张）、「返回」退回网格
- 点空白处返回

照片存在 `/sdcard/HomeGuard/`，直接删文件也会在下一次进相册时刷新。

## 三、四个必须记住的坑（都踩过并已解决）

### 1. `Camera.open()` 在这台机器上永远返回 null

这台设备**只有前摄、没有后摄**，而 `Camera.open()` 的无参版本只找 `CAMERA_FACING_BACK`，找不到就 `return null`。

```java
cam = Camera.open(0);   // 必须指定编号，不能无参
```

顺带：`getSupportedPreviewSizes()` 只返回 **1920×1080** 一个尺寸，没得选。

### 2. 摄像头是单客户端，原厂会议 App 会一直抱着不放

Android 4.4 全局只允许一个相机客户端，**先到先得**，后来者 `Fail to connect to camera service`。

- 原厂 `vulture.app.home` 只要打开过「录像机」或会议界面，就会一直持有相机（退回桌面、按 BACK 都不放）
- **普通应用拿不到 root**：`Runtime.exec("su -c id")` 返回 `rc=1`

解法：`/data/local/tmp/cam_guard.sh`（root 守护，随开机启动）
- 看家 open 失败 → 写 `/sdcard/HomeGuard/.need_cam`
- 守护每 2 秒检查该文件 → 确认相机确实被占 → `am force-stop vulture.app.home` → 删标志
- 看家每 2.5 秒重试 open，直到抢到（实测 10 秒内完成）

进程被杀后系统会重新拉起对方，但那时相机已经先到先得在看家手上，**它抢不走**。

```sh
sh /data/local/tmp/cam_guard.sh status   # 是否在跑
sh /data/local/tmp/cam_guard.sh stop     # 停
/sbin/busybox tail -20 /data/local/tmp/cam_guard.log
```

### 3. Android 4.4 发不出 QQ 邮件（两个独立原因）

**(a) 系统根证书库太老**：`Trust anchor for certification path not found`，QQ 现在用的 CA 不在 4.4 的信任列表里。
→ 用自定义 `X509TrustManager` 宽松校验收口（仅用于本机发信通道）。

**(b) 默认不启用 TLS 1.2**：必须显式打开。
```java
s.setEnabledProtocols(new String[]{"TLSv1.2", "TLSv1.1", "TLSv1"});
```

另一个后续坑：`EP` 阶段返回 **550 The "From" header is invalid**。
RFC2047 的 `=?UTF-8?B?...?=` **只能编码显示名，地址必须留在外面**：
```
From: =?UTF-8?B?VDcwTOeci+Wutg==?= <your-email@example.com>   ✓
From: =?UTF-8?B?VDcwTOeci+WutSA8Li4uPg==?=                ✗
```

### 4. 1080p 预览会把 GC 拖死

`setPreviewCallback` 每次分配 3MB 的 `byte[]`，15fps 就是 45MB/s 的垃圾 → GC 占 22% 一个核，整机 74%。

→ 改 `setPreviewCallbackWithBuffer` + `addCallbackBuffer` 复用缓冲，用完再还。
**GC 从 22% 降到 0，整机从 74% 降到 39%（约 6.5%）**。

## 四、技术选型说明

| 环节 | 方案 | 为什么 |
|---|---|---|
| 人脸检测 | 系统自带 `android.media.FaceDetector` | 零依赖、API1 就有；320×180 下每次约 200ms |
| 抓拍 | `YuvImage.compressToJpeg` 直接吃 NV21 | 不转 Bitmap，省 8MB 内存 |
| 邮件 | 手写 SMTP（465 SSL / 587 STARTTLS / 25 明文） | 不引 JavaMail（会大 300KB） |
| 预览承载 | 服务自建 `SurfaceTexture`（离屏） | 切到任何界面都不中断；界面只显示最近抓拍 |
| 检测尺度 | 480×270（1080p 的 1/4） | 再小会漏检远处人脸；实测眼距 20–32px，置信度稳定 0.51 |

**误报控制**：`confidence ≥ 0.35` **且** `眼距 ≥ 16px`，两个条件同时满足才算命中。眼距太小说明是纹理误检。

## 六、已知限制

1. **看家运行时原厂会议/录像功能不可用**（摄像头只有一个，被看家占着）。退出看家后自动恢复。
2. 从待机冷启动到抢到相机约 2–10 秒（要先让原厂让出）。
3. `FaceDetector` 对侧脸、低头、大逆光不敏感，正脸识别率最高。
4. 邮件是同步发送，网络差时该次可能失败并计入"发送失败"，照片仍留在本地。
5. 息屏状态下相机帧率会掉一半（驱动省电），所以跳帧间隔改成按屏幕状态自适应；
   响应仍然在 1 秒量级，不影响"人进门就拍"。

- **2026-11-06 三版**：

    改成显式判退出码，失败即停

- **2026-11-06 四版**：
  - 相册新增**大图预览**：长按照片全屏看原图，左右滑动切换、双指缩放（1~4x）+ 放大拖动、
    单张删除（自动切下一张）、点空白返回

- **2026-11-06 五版（回退 + 修死循环，重要）**：
  - **撤掉实时预览**，回到"只抓拍、画面静止"的原始设计。
    实时画面是把每帧 NV21 在 Java 层手转 RGB（480×270），每帧要新建
    `int[129600]`（约 518KB）+ 一张 Bitmap（约 260KB）。实测界面开着时
    GC 每 0.9 秒强制回收一次、每次 2.2MB，CPU 白烧 —— 这台 1GB 的盒子扛不住，
    而用户要的只是"有人进门留一张照片"，所以实时画面没有价值。
  - **修一个从首版就存在的致命 bug**：`onPreviewFrame` 里提交给工作线程的任务
    只有一个 `catch`，缺 `finally`。`detectAndShoot()` **正常返回**时既不 `busy = false`、
    也不 `camera.addCallbackBuffer()` —— 于是**每次启动只能抓拍到第一张**，之后
    `busy` 永远为真，所有帧都走"直接归还"分支，相机 1080p 预览空转到底，
    再也不检测、不抓拍、不发邮件。已在字节码层确认（`GuardService$8.字节码`：
    `:try_start_0 → goto :goto_0` 直接 return，只有 `:catchall_0` 路径才复位 `busy`）。
    改法：`try / catch / finally`，finally 里复位 `busy` 并归还缓冲。
  - 增加兜底：`busy` 超过 20 秒没释放就强行解锁（防止 `FaceDetector` 卡死工作线程）。
  - `FACE_GONE_MS` 45 秒 → **20 秒**：人脸消失超过 20 秒再出现，就无视冷却立刻抓一张。
    这样"人来了→走开→又回来"这一趟不会被 60 秒冷却吞掉；一直站着不动仍然只有 60 秒一张。
  - `detectEvery()` 的判定不变（亮屏 12 帧 / 熄屏 3 帧），实测约 1 次/秒。
  - 主界面刷新从 300ms 改成 1000ms（`loadLatest()` 本身按文件 mtime 做了缓存，
    没新照片不重复解码），并把提示文案改回"显示最新抓拍"。
  - **实测**：连续运行 2 分钟，`detect n=` 稳定 1 次/秒，按 60 秒冷却持续产出新照片
    （18:27:56 → 18:29:31），`com.lm.guard` 常驻 CPU 约 4%（相机 HAL 另占 mediaserver 6%），
    20 秒内 GC 次数从 22 次降到 3 次。
  - 注意：这颗 HAL 只支持一档帧率 `[3000-60000]`，**没法通过 `setPreviewFpsRange` 降帧**；
    想再省 CPU 只能降预览分辨率（当前 1920×1080 → AK 抓拍 160KB/张），暂未改，因为 4% 已经很低。
  - 备份：`guard-SNAP-20261106-1830.apk`（本版）、`guard-GOOD-20261106-1800.apk`（上一版，含实时画面）。
