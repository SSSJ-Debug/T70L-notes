# 桌面系统化（给 com.xylink.launcher 补 BIND_APPWIDGET）

> 2026-11-01。目的：让原厂桌面具备绑定 Android 小组件（AppWidget）的权限。
> 结果：**成功**，权限已生效且重启稳定。

---

## 一、为什么要做

原厂桌面 `com.xylink.launcher`（MarlinLauncher，v1.3.0-161）是 OEM 的**静默安装器**
装到 `/data/app/MarlinLauncher.apk` 的，属于**普通第三方应用**，拿不到：

```
android.permission.BIND_APPWIDGET   (protectionLevel=18 = signature|privileged)
```

开机日志实证：
```
W/PackageManager: Not granting permission android.permission.BIND_APPWIDGET
                  to package com.xylink.launcher (protectionLevel=18 flags=0x58be44)
```

**保护级别 18 = signature|privileged**，只有系统镜像上的应用（`/system/priv-app`）才会被授予。

---

## 二、怎么做的（完整步骤）

### 2.1 备份（必须先做）

```bash
adb pull /data/app/MarlinLauncher.apk  ~/re-tools/t70l/repair_20261101/MarlinLauncher.apk.bak
# 238035 字节，md5 8e16288497ecd06225320e91c3ebab62，package com.xylink.launcher v1.3.0-161
```

同时备份桌面数据库：
```bash
adb pull /data/data/com.xylink.launcher/databases/_setting.db \
         ~/re-tools/t70l/repair_20261101/launcher_db/_setting.db.bak
```

### 2.2 复制到 priv-app

```bash
adb push MarlinLauncher.apk.bak /data/local/tmp/ml.apk
adb shell "md5 /data/local/tmp/ml.apk"          # 必须与备份 md5 一致才继续

adb shell "mount -o rw,remount /system"
adb shell "cp -f /data/local/tmp/ml.apk /system/priv-app/MarlinLauncher.apk"
adb shell "chown 0:0 /system/priv-app/MarlinLauncher.apk"
adb shell "chmod 644 /system/priv-app/MarlinLauncher.apk"
adb shell "chcon u:object_r:system_file:s0 /system/priv-app/MarlinLauncher.apk"
adb shell "sync"
adb shell "mount -o ro,remount /system"
```

> `chcon` 会报 `Permission denied`（shell 域无 relabel 权限），
> 但文件标签本来就是 `system_file:s0`（`cp -f` 复用 inode），
> 用 `ls -lZ` 确认即可，**不用为此反复重试**。

### 2.3 重启验证

```bash
adb shell reboot
# 约 26 秒开机
```

验证三项：
```bash
# 1) 权限拒绝消失
adb shell logcat -d | grep -c "Not granting permission android.permission.BIND_APPWIDGET"
#   → 0

# 2) 桌面从系统分区启动
adb shell pm path com.xylink.launcher
#   → package:/system/priv-app/MarlinLauncher.apk

# 3) 桌面在前台、能正常显示
adb shell dumpsys activity | grep mFocusedActivity
#   → com.xylink.launcher/.app.LauncherActivity
```

## 三、为什么风险可控

| 风险 | 实际情况 |
|---|---|
| 桌面起不来 → 黑屏 | 最低可能：`/data/app` 的原始副本**保留不动**，系统分区只是多一个同签名 APK。PMS 若拒绝，会继续用 `/data/app` 那份 |
| 用户数据丢失 | 桌面数据库、图标位置都在 `/data`，不受影响 |
| 签名冲突 | 用的是**同一个 APK 文件**，签名完全一致 |
| 回滚 | 删 `/system/priv-app/MarlinLauncher.apk` → 重启，即回到原状态 |

实际执行结果：一次成功，重启后桌面正常、布局未变、权限生效。

---

## 四、副作用 / 注意

1. 桌面现在算"系统应用"，OEM 的**静默更新通道**以后可能覆盖不了它（签名不同）——
   对我们反而是好事，防止被云端回锁。
2. 权限解决的是"能不能绑定组件"，**没有解决"桌面根本不申请组件 id"这个逻辑缺陷**。
   详见 `天气卡片与天气App.md` 第三节。
3. 以后若刷回官方 OTA，这个 priv-app 副本会被覆盖/清除，属正常。
