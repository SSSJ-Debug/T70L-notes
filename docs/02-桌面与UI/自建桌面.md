# 自建桌面 NemoDesk —— 让 T70L 拥有可拖动的安卓桌面

> 目标：原厂桌面（`com.xylink.launcher`）的图标位置是写死的，不能拖、不能长按卸载。
> 我们另写了一个桌面，图标尺寸与原厂**像素级一致**，同时具备完整拖动与长按菜单。

---

## 一、为什么必须自建

原厂桌面 `com.xylink.launcher`（MarlinLauncher 深度改造）的渲染流程：

```
_setting.db → item_info 表 → icon 字段(BLOB) → ImageView 直接贴图
```

我们把整个 APK 的 字节码 过了一遍，确认：

| 能力 | 原厂 | 说明 |
|---|---|---|
| 图标位置 | 写死在 `cellX/cellY` | 只能改数据库，不能用手拖 |
| 拖动 | **不存在** | `DragController` / `DragLayer` 在整包里查无此类 |
| 长按菜单 | 无 | 长按无响应 |
| 多屏 | 有（底部三个页面点） | 固定分页 |

`startDrag` 方法只出现在 support 库（v4/v7）里，主包从未调用。
也就是说：**这个桌面的拖动能力根本不存在，不是被锁，是没写。**

所以只能自己写一个。

## 二、图标尺寸怎么做到"一模一样"

### 2.1 先搞清楚原厂的卡片规格

从数据库导出的 BLOB 是 **220×280 PNG**，但里面不是满幅内容：

```
画布        220 × 280
可见卡片    190 × 250   （左 15、右 16、上 20、下 11 的透明边距）
圆角        约 14px
```

原厂 launcher 是**按 BLOB 原始尺寸 220×280 直接铺开**，不做缩放。

### 2.2 实测验证（用程序量像素）

对同一张"电话"卡片，在两张 1280×800 截图上扫描亮色区：

```
原厂桌面 home9.png   →  x 660..839  (w=180)   y 440..679  (h=240)
新桌面  deskN1.png   →  x  70..249  (w=180)   y 216..455  (h=240)
```

**宽 180、高 240，完全一致。**

### 2.3 关键参数（源码里的常量）

```java
CARD_W = 220;   // 显示尺寸 = BLOB 原始尺寸，绝不缩放
CARD_H = 280;
ART_W  = 220;   // 合成第三方卡片用的画布，与原厂 BLOB 同规格
ART_H  = 280;
ART_R  = 14;    // 圆角
```

### 2.4 文字是 launcher 画的，不在图里

把 `orig_72.png` 单独打开看，**只有渐变底色 + 白色图标，没有文字**。

原厂渲染逻辑是：`BLOB 贴图` + `TextView 叠加标题`。

所以新桌面也必须分两层：

```java
ImageView  // 整张 220×280 卡片图，FIT_XY 铺满
TextView   // 标题，22→26px，白字，距底 34px，居中
```

内置卡片和第三方卡片走**同一套文字参数**，视觉才统一。

### 2.5 第三方应用怎么合成同规格卡片

运行时用 Canvas 画一张 220×280 位图：

```java
private Bitmap makeArt(Bitmap src, String title, int light, int dark) {
    // 1. 圆角裁剪
    // 2. 对角渐变（起点 0,0 → 终点 220*0.45, 280*0.55）
    // 3. 图标居中偏上：56×56，top=56（中心 y≈84，原厂为 70–99）
    // 4. 无图标的应用 → 画名称首字，92px 白色粗体
}
```

渐变方向、圆角、图标位置全部对齐原厂数值。

## 三、踩过的坑（每条都是真坑）

### 3.1 d8 编译崩溃：`NullPointerException: String.length()`

```
Error in obj/.../MainActivity$1.class:
java.lang.NullPointerException: Cannot invoke "String.length()" because "<parameter1>" is null
```

**原因**：build-tools 34.0.0 自带的 **R8 8.2.2 有 regression**。
当匿名类定义在**字段初始化**处（不是方法里）时，javac 会生成
`EnclosingMethod: #14.#0`（method_index = 0），R8 8.2.2 处理不了这个结构。

**两种解法**（都做了）：

1. 把字段初始化的匿名类改成具名内部类
   ```java
   private Runnable ticker;              // 字段只声明
   ticker = new Ticker();                // 构造函数里再赋值
   private class Ticker implements Runnable { ... }
   ```
2. 换掉有 bug 的 R8 —— 用 **8.5.35**
   ```
   $HOME/re-tools/r8/r8-8.5.35.jar
   java -cp <jar> com.android.tools.r8.D8 --min-api 15 --lib android-19.jar --output dex ...
   ```

> build.sh 里已经把 d8 换成 8.5.35，注释也写清楚了原因。别改回去。

### 3.2 第二行图标不显示

用 `view.setX()/setY()` 定位，第一行正常，第二行完全不见。

**原因**：`setX/setY` 设的是 `translationX/Y`，**translation 不参与父容器测量**。
FrameLayout 测量的高度只包住第一行，第二行被 `clipChildren` 裁掉了。

**解法**：布局用 `LayoutParams.leftMargin/topMargin`，拖动时才用 translation：

```java
clp.leftMargin = offsetX + cellX * cellW;
clp.topMargin  = cellY * cellH;
```

拖动结束再 `place()` 把 margin 落回去、清掉 translation。

### 3.3 拖了没反应（弹回原位）

第一次实现是"拖到空位就移动，否则找最近空位"，结果格子里排满时
所有卡片都弹回原处，看起来像"拖不动"。

**解法**：改成**交换位置**（安卓桌面标准行为）——
目标格有卡片就和它换，没有就直接落位。

### 3.4 卡片套卡片（双层背景）

一开始把 `orig_72.png`（已经是完整卡片图）塞进又一个渐变背景里，
视觉效果就是"卡片里还有一张小卡片"。

**解法**：卡片图整张直出，`c.nativeArt = true` 时不再叠任何背景。

### 3.5 布局高度基准取错

`DisplayMetrics.heightPixels` 返回 **752**（扣掉了 48px 状态栏），
但本桌面是全屏主题，实际绘制区是 **800**。
用 752 算行高，第三行就会露出 48px 的半截卡片。

**解法**：

```java
Point real = new Point();
getWindowManager().getDefaultDisplay().getRealSize(real);
screenH = real.y;   // 800
```

| 功能 | 实现 |
|---|---|
| 图标自由拖动 | 长按 0.4s 浮起拖动，或直接滑动拖动（超 12dp 判定） |

## 五、已知限制

### 5.1 HOME 键在这台设备上被固件屏蔽

不是我们弄坏的，是会议终端的 kiosk 设计。证据：

- 按 HOME 键，logcat 只有 `injectKeyEvent`，**没有任何 ActivityManager 的 START 记录**
- `mHomeProcess` 已经指向 `com.nemo.desk`，但 HOME 键依然无动作
- 系统 `package-restrictions.xml` 里出厂就把首选 HOME 写死：
  ```xml
  <preferred-activities>
    <item name="vulture.app.lanucher/.LauncherActivity" match="100000" always="false">
      <filter> MAIN + HOME + HOME_NEMO + DEFAULT </filter>
    </item>
  </preferred-activities>
  ```
- 尝试改这个配置、删掉整段、换 match 值、加 `HOME_NEMO` category —— **全部无效**，
  只会让 HOME 彻底失效（因为解析失败后不 fallback）

**结论**：不要去动 `package-restrictions.xml`。原始备份就在 `nemodesk/package-restrictions.xml.bak`，
万一改坏了，push 回去 + 重启即可。

### 5.2 所以用开机自启代替

> 🔴 **2026-11-01 P0 事故警告（先读这段再动手）**
> 下面这个块本身是"有限次等待"、没有死循环，是安全的种子。
> **但后来有人在同一个位置追加了一段 `while true` 去常驻 `app_process`，
> 直接导致设备每 3 秒崩一次、`/data` 灌到 832MB、反复进安全模式重启，差点报废整机。**
> 完整事故见 `故障复盘-开机崩溃.md`。
>
> **往 `install-recovery.sh` 里写任何东西之前，必须遵守：**
> 1. 循环必须有上限（`n -lt N`），到点 `break`/`exit`，**永不用 `while true`**
> 2. 要执行的命令必须先在设备上手动跑通 3 次
> 3. 只做"拉一次"，常驻服务别往这里塞
> 4. 改前先从固件镜像取原厂文件备份，改后 `md5` 复核

`/system/etc/install-recovery.sh` 追加：

```sh
(
  i=0
  while [ "$(getprop sys.boot_completed)" != "1" ]; do
    sleep 1
    i=$((i+1))
    if [ $i -gt 180 ]; then break; fi
  done
  sleep 15
  am start -n com.nemo.desk/.MainActivity >/dev/null 2>&1
  log -t nemodesk "desk autostarted"
) &
```

重启后约 60 秒，桌面自动切到 NemoDesk。

### 5.3 部分系统应用显示安卓机器人

`Airhub`、`ScreenSaver`、`widgetclock`、`widgetweather`、`speech_app` 这些内置应用
**自带的就是一张安卓机器人图标**（不是系统默认兜底图），
像素比对识别不出来，所以会原样显示。

处理办法：长按 → 卸载应用，直接清掉。清理后桌面会非常整齐。

## 七、想加新图标怎么办

**方式 A：从原厂桌面抄一张现成的**

原厂卡片都存在数据库 BLOB 里，直接导出：

```bash
adb shell "su 0 sqlite3 /data/data/com.xylink.launcher/databases/_setting.db \
  \"select _id, title from item_info where iconType=2\""
```

导 BLOB → `res/drawable-nodpi/orig_XX.png` → 在 `loadCards()` 里 `addBuiltin(...)`。

**方式 B：装的第三方应用自动出现**

`onResume` 会自动扫描 `CATEGORY_LAUNCHER`，新装的应用会自己长出来，
并按同一套 220×280 规格合成卡片。

## 八、一句话总结

原厂桌面没有拖动能力 → 自己写一个 → 卡片规格按 BLOB 原始 220×280 直出、
显示 180×240、文字层参数统一 → 用 margin 定位避开 translation 不参与测量的问题 →
拖动做成交换式 → 长按菜单接 `pm uninstall` → HOME 键被固件屏蔽就用开机脚本兜底。
