# T70L 桌面标准（图标 + 布局）

> 这套标准是 2026-11-02 凌晨到早上，反复试错 7 版音乐图标后定下的。
> 目标：桌面上任何图标看起来都和原厂图标**完全一致**，装新应用也不会破坏整体感。

---

## ★ 新软件必读：为什么"每做一个新 App，图标都大一圈"

**这是本文件最重要的一节。做任何新软件、要往桌面放图标之前，先读完。**

### 结论分两层，第二层是 2026-11-08 才挖出来的

**第一层（2026-11-02 解决）：画布 ≠ 实体**

桌面**不做任何缩放，1:1 原样绘制这张 PNG**。所以"画布 220×280 对了"不等于"大小对了"，
真正决定大小的是画布里那张实心卡片占多大：

| | 原厂图标 | 早期我们做的（错） |
|---|---|---|
| 画布 | 220×280 | 220×280 ✅（所以一直以为对了） |
| 实心卡片 | **180×240**，四周各留 20px | 203×265，四周只留 8px |
| 桌面渲染 | 180×240 | 205×262 → 宽 14%、高 9% |

**第二层（2026-11-08 挖出的真正病根）：实体对了，图形照样大**

用户第二次说"听歌、抖音的图标还是偏大一圈"。这次逐像素验到底，结论是：
**卡片尺寸已经 100% 正确，大的是卡片里的图形。**

证据一 —— `uiautomator dump` 抓的 View bounds，8 个格子完全一致：

```
文件夹 [200,140]-[420,420]  220x280
录像机 [420,140]-[640,420]  220x280
小智   [200,420]-[420,700]  220x280
听歌   [440,420]-[660,700]  220x280   ← 和原厂一样的格子
```

证据二 —— 截图逐像素扫，8 张卡片宽度**全是 180**，高度全是 240。

证据三 —— 卡片里图形占多宽（卡片宽 180）：

| 图标 | 图形尺寸 | 占比 |
|---|---|---|
| 原厂 文件夹 | 64×57 | **36%** |
| 原厂 录像机 | 54×56 | **30%** |
| 原厂 设置 | 54×41 | **30%** |
| 翻车前 听歌 | 120×95 | **67%** |
| 翻车前 抖音 | 101×88 | **56%** |
| 翻车前 小智 | 113×92 | **63%** |

**差不多是原厂的 2 倍。** 机制原因在 `mk_icon.py`：输入不是 220×280 时走
`cover_fit`（等比**覆盖**填满 180×240），任何 App logo 一进去就被放大到撑满卡片 ——
所以"每做一个新软件就大一圈"，一次都没跑掉。

### 第三层（2026-11-08 下午 · 最要命的一层）：桌面自己会把 APK 图标重画一遍

前两层都修好了，图标还是会"隔几天又大一圈"。第三层的原因是：

**桌面在收到装包/换包广播（`pm install` 也算）时，会把第三方应用的条目整行重建**，
重建时不用你库里的 BLOB，而是**拿 APK 里的 launcher 图标重新合成**：

```
把 APK 的 icon 等比缩到【宽 120】
  → 居中贴到桌面自己画的卡片上
  → 把整张合成图存成一个【满铺 220×280】的 icon BLOB
```

所以最终形态是：

| | 数值 |
|---|---|
| 外层卡片（桌面画的） | 220 宽，满铺，实体 @(0,0) |
| 里面那张卡（我们的 180×240 被缩） | 180 × 120/220 = **98 宽** |
| 图形占卡片宽 | 98/180 = **54%** ← 又超了 |

而且视觉上是**"卡片里套一张卡片"**（深色外卡 + 我们的彩色内卡），一眼就不对。

**结论：只修数据库治不住，下一次 `pm install` 必然重画。**
`launcher_guard.sh` 因此新增 `sync_icons()`：14 条标准条目逐条与模板库**字节比对**，
不一致就用模板覆盖；触发点 = 包变化立即 + 每 60 秒巡检 + `restore_layout()`。

> 注意：守护修的是**数据库**，桌面界面有内存缓存，屏幕要等桌面进程重进一次才变。
> 需要时 `am force-stop com.xylink.launcher` + `input keyevent 3`（**只做一次**，别循环）。

### 正确做法：新软件走 mk_app_icon.py，一条命令

```bash
# 1. 准备一个方块 logo（PNG，背景透明最好，512/1024 都行）
# 2. 一条命令出标准图标（--bg 用 App 主色）
python3 $HOME/re-tools/t70l/launcher_standard/mk_app_icon.py \
    --logo 音符.png --bg 6E46E6 听歌.png

# 3. 必须校验，图形占比 > 45% 不许上桌面
python3 $HOME/re-tools/t70l/launcher_standard/check_icon.py 听歌.png
```

`mk_app_icon.py` 做的事：卡片 180×240（`--bg` 竖向明暗）+ logo 等比缩到
最长边 64（`--box`）+ 居中放在卡片内 y=64（`--cy`）+ 套原厂圆角/投影。

`check_icon.py` 现在多打一行 **「图形 54x64，占卡片宽 30%」**，超 45% 直接提示
「比原厂大」。**这是唯一能防"下次又忘"的闸门，必须看这一行。**

### 已经偏大的老图标怎么救

```bash
# fit 模式：彩色卡片 + 单层图形（文件夹那种）
python3 icon_content_fix.py 旧.png 新.png --mode fit

# light 模式：暗卡片 + 白色 logo（听歌/抖音/小智就是这种）
python3 icon_content_fix.py 旧.png 新.png --mode light --bg 6E46E6 --thr 130
```

light 模式只抠"亮部图形"，换掉卡片底色后重新贴。
为什么需要它：抖音那种"卡片里套卡片"的图，直接把内层黑方块缩到 64，
方块里的 d 会一起缩成 20 多像素，糊成一团 —— 必须先把 d 抠出来单独缩放。

### 三条铁律（2026-11-08 修订）

1. **不要从零手绘 220×280，也不要用 `mk_icon.py` 的 cover 模式喂 logo。**
   新软件一律 `mk_app_icon.py`（logo 最长边 64）。
2. **实心区必须 180×240 @ (20,20)，图形宽 ≤ 64（= 卡片宽 36%）。** 写完跑 `check_icon.py`，
   图形占比 > 45% 不许写进桌面库。**APK 里的 `ic_*.png` 和桌面库 BLOB 必须用同一张图。**
3. **卡片底色别选"比背景亮一点点"的中间色。** 桌面背景约 `#1E2030`；
   听歌原来用 `#262F48`，只差 8/16/27，卡片边界基本看不见，
   于是只剩中间那个大图形浮在背景上 —— 视觉上就是"大一圈"。
   **要么明显亮（品牌主色），要么明显暗（近黑），别卡在中间。**
4. **（2026-11-08 新增）别指望"改好了就一劳永逸"** —— 桌面会在装包时用 APK 图标重画条目，
   守护的 `sync_icons()` 会在 20 秒内按模板复位。构建脚本必须带 `check_icon.py` 门禁。

### ★ 第四条：图形别占满，底部 1/3 要留给标题

桌面**把标题画在卡片内部**，基线大约在卡片的 **78%** 高度（240 高的第 188 行附近）。
主体图形如果按"满铺 240"去画，底部必然压到字上 —— 2026-11-06 云台调节的下箭头
就压在"云台调节"四个字上，看家的盾牌也顶到了"看家"。

| | 建议值 |
|---|---|
| 图形上沿 | `y ≈ 25~35`（卡片内坐标） |
| **图形下沿** | **`y ≤ 165`**（留 75px 给标题） |
| 视觉中心 | `y ≈ 64`（`mk_app_icon.py` 的默认 `--cy 84` 就是按这个折算的） |

### 事故记录

- **2026-11-06** 云台调节：画布做对、卡片做成 203×265，桌面渲染 205×262，比原厂宽 23px。
  根因是**没有复用 `mk_icon.py`，每次从零画**。修复后补了 `check_icon.py` 做门禁。

- **2026-11-06 下午（换图标）** 看家/云台的主体画到了 `y=182 / y=188`，`check_icon.py`
  照样 PASS，但上桌面后云台的下箭头直接压在标题上。→ 补了上面"第四条铁律"。

- **2026-11-06 下午（守护脚本笔误）** `STD` 里写的是 `看家:1:0:1:guard`，
  而库里真实 kind 是 `x`。于是每 10 秒判一次"不符"→ 整表恢复一次。
  **教训：加条目时 kind 一定要抄库里已有的写法（`x`/`rec`/`w`…），别自创。**

- **2026-11-08（本条最贵，犯了好几次才发现）** 用户第 N 次指出"听歌、抖音图标大一圈"。
  前几次都以为"画布对了就对了"，其实**卡片早就是 180×240，大的是图形**。
  真凶是 `mk_icon.py` 的 `cover_fit`：把 App logo 等比**填满**卡片。
  修复：新增 `mk_app_icon.py`（logo 缩到 64）+ `icon_content_fix.py`（救老图）+
  `check_icon.py` 增加图形占比输出。听歌 67%→30%、抖音 56%→27%、小智 63%→36%。

## ★ 第二条命门：图标放上去会"自己消失"，是守护脚本干的

同一件事的另一半。**新应用的图标放进库后过一会儿就没了 / 桌面被还原**，不是桌面抽风，
是 `/data/local/tmp/launcher_guard.sh` 在按"标准签名"巡检：

```
STD='...9 个条目的 title:screen:cellX:cellY:kind...'
```

每 10 秒算一次全表签名，**和 STD 不一致就修**；修不好（连续 2 次）就走兜底 `full_restore()`：

```sql
DELETE FROM item_info;                     -- ← 整表清空
INSERT INTO item_info SELECT * FROM bak.item_info;
-- bak = /data/local/tmp/_setting.db.bak-privacy（模板库）
```

**模板库里没有的条目，一轮就被清掉。** 而且清理是每 10 秒一轮、静默的，看起来就像"图标自己跑了"。

### 所以新增一个桌面图标，必须同时改三处（少一处就白干）

| # | 改哪里 | 内容 |
|---|---|---|
| 1 | `/data/local/tmp/_setting.db.bak-privacy`（模板库） | 插一行，坐标与 intent 与正式库一致 |
| 2 | `launcher_guard.sh` 的 `STD` 签名 | 按 title 的 UTF-8 字节序插入 `云台调节:1:3:0:x`（`x` = 普通快捷方式） |
| 3 | `launcher_guard.sh` 的 `restore_layout()` | 加一行 `ensure_from_tpl 云台调节`，被删了能自动补回 |

改完：

```bash
adb push launcher_guard.sh /data/local/tmp/ && \
adb shell 'sh /data/local/tmp/launcher_guard.sh stop; sleep 1; sh /data/local/tmp/launcher_guard.sh start'
adb shell 'sh /data/local/tmp/launcher_guard.sh check'    # 必须回 OK 布局与标准一致
```

签名排序按 **UTF-8 字节序**（不是拼音、不是笔画）：
`云`(E4BA91) < `哔`(E59394) < `天`(E5A4A9) < `录` < `文` < `时` < `灯` < `电` < `看` < `设`。

## 一、为什么需要把它固定下来

桌面布局存在 `/data/data/com.xylink.launcher/databases/_setting.db` 的 `item_info` 表里。
这张表有两个特性，导致状态容易"自己变回去"：

1. **装 APK 会触发桌面重建**。重建时按 `_id` 顺序、从左上角开始"首次适配"自动填充格子，
   用户排好的位置会被冲掉。
2. **第三方应用的图标会被写成"满铺 220×280"**，而原厂图标实体只有 180×240，
   所以新图标看上去比原厂大一圈（音乐图标最初就是这样）。

所以：**布局和图标都必须有标准 + 可一键恢复**，不能靠手调。

## 二、图标硬规格（逐像素实测，不要凭感觉改）

以原厂「文件夹」「录像机」为基准，解 PNG 量出来的真实数据：

| 项目 | 数值 | 说明 |
|---|---|---|
| 画布 | **220 × 280** RGBA | 所有桌面图标统一尺寸 |
| 实体 | **180 × 240** | 位于 `(20,20)` ~ `(199,259)`，四角圆角 |
| 实体轮廓 | alpha ≥ 60 的范围正好是 180×240 | 圆角过渡在 1~3px 内完成 |
| **投影** | **颜色固定 `(26,25,33)`** | 实体下方 `y=260~277`，alpha 55→0 线性衰减 |
| 不透明总范围 | `(7,12)` ~ `(212,277)`，即 **206 × 266** | 含投影 + 左右上极淡过渡 |
| 实体色 | 各图标自己的渐变 | 文件夹紫 `(116,16,255)`、音乐橙红 |

### ★ 最容易踩的坑：投影必须是黑色

**原厂的投影是黑色阴影 `(26,25,33)`，不是主体颜色。**

我一开始把投影区填成了图标主体色（橙色），结果在深色背景上，音乐底部泛出一圈明显的橙色光晕，
而文件夹（紫色）因为对比度低看不出问题。这就是"就差底下这条边框"的根因。

**结论：投影区一律 `(26,25,33)`，与主体颜色无关。**

### 另一个坑：不要做"整圈柔光"

只有**下方**有投影；左、右、上只有 1~2px 的极淡过渡。
如果按"四周都加柔光"处理，会得到一圈多余的透明边。

### 2. 恢复与维护


## 四、标准布局

### 第一屏（screen = 0）

| 位置 | 内容 | 尺寸 |
|---|---|---|
| (0,0) | 时间（时钟组件，含农历+干支） | 2×1 |
| (2,0) | 天气（辽阳，温度/霾/空气质量） | 2×1 |
| (0,1) | 电话 | 1×1 |
| (1,1) | 日程 | 1×1 |
| (2,1) | 消息中心 | 1×1 |
| (3,1) | 设置 | 1×1 |

时间与天气**在同一行**，下面一行四个图标——这是调过多轮才定下的视觉平衡。

### 第二屏（screen = 1）

| 位置 | 内容 |
|---|---|
| (0,0) | 文件夹 |
| (1,0) | 录像机 |
| (2,0) | 音乐 |

### `_id` 顺序也是标准的一部分

`_id` 依次为 1 时间 → 2 天气 → 3 电话 → 4 日程 → 5 消息中心 → 6 设置 → 7 文件夹 → 8 录像机 → 9 音乐。

**为什么要在意 `_id`**：桌面重建时按 `_id` 顺序填充。只要这个顺序 = 期望的视觉顺序，
即使重建，自动填充也能得到正确结果。否则重建后必然错位。

## 五、装新应用之后要做的事（2026-11-08 修订）

1. **出图标**（别手绘）：
   ```bash
   python3 mk_app_icon.py --logo logo.png --bg 品牌色 输出.png
   python3 check_icon.py 输出.png      # 图形占比必须 ≤ 45%
   ```
2. **写库三处一起改**（少一处就白干，见上面"第二条命门"）：
   正式库 `_setting.db` + 模板库 `_setting.db.bak-privacy` + `launcher_guard.sh` 的 `STD`。
3. **桌面进程要先停干净**：
   ```bash
   adb shell "sh /data/local/tmp/launcher_guard.sh stop"
   adb shell "am force-stop com.xylink.launcher"
   # 推库 → rm -f _setting.db-journal → chmod 660
   adb shell input keyevent 3
   ```
   注意：`am force-stop` 后系统可能秒重启桌面，用它内存里的旧模型把我们的行冲掉。
   **2026-11-08 实测**：推完库再 `input keyevent 3`，桌面启动时会扫描已安装应用，
   把"库里有条目但包已卸载"的和"包还装着但库里没条目"的都按自己的规则处理 ——
   所以**卸载 APK 要在推库之前做完**（火狐就是这么被加回来的，PLDroid 是包没卸干净）。
4. **上桌后必须量一次**：截图量卡片边缘，8 个格子宽度必须都是 180；图形占卡片宽 ≤ 45%。
5. 如果布局被打乱，跑 `./restore.sh full`（会先自动备份）。

### 卸载应用时的坑（2026-11-08）

- `pm uninstall` 成功 ≠ 桌面条目消失；桌面条目在库里，得自己删。
- 反过来说，**只删桌面条目不卸包，桌面一重启就把图标加回来**（PLDroid 就这样复活了）。
- 正确顺序：**先 `pm uninstall`，再删两库里的行，再改 `STD`，最后启动桌面**。
