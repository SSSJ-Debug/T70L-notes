原厂壳与我们自编译的 APK **签名不同**，直接 `install -r` 会报：
```
Failure [INSTALL_PARSE_FAILED_INCONSISTENT_CERTIFICATES]
```
所以顺序固定：`uninstall` → `install`。

### 最终版本（带秒针的那个）

**用 `~/re-tools/t70l/widget_build/timewidget-sec.apk`，不要用 `tw/nemoclock.apk`。**

| 版本 | 位置 | 特征 |
|---|---|---|
| 带秒版（**定稿**） | `widget_build/timewidget-sec.apk` | 24 小时制 `13:23:48`（秒为小字）+ 农历；Service 每秒推 RemoteViews |

### ★ 重要更正：卡片绑定会自愈，不用手写 appwidgets.xml

本文档第七节曾写「组件槽位是坏的、必须写开机重绑脚本」——**该结论已作废**。

2026-11-04 实测：`uninstall` 后系统会删掉旧绑定，`install` 后重启桌面进程，
Launcher 会**自己**调 `allocateAppWidgetId()` 拿新 id 并回写 `item_info`：

```
重启前: 时间 appWidgetId=16, 天气=17
重启后: 时间 appWidgetId=60, 天气=61   ← Launcher 自己重新分配
appwidgets.xml 同步出现 <g id="3c" p="0"/>(时间) <g id="3d" p="1"/>(天气)
```

**整机重启后依然正常，秒针继续走、天气照样有数据** —— 不需要任何 `/system` 写入，
也不需要开机重绑脚本。所以「写 `/system` 才能常驻」这条路**没必要走了**。

## 0. 一句话结论

这台设备的桌面本身**不画时钟、也不画天气**——它们都是标准 Android AppWidget。
所以给桌面加功能不需要动桌面 APK，只要**替换组件实现**就行。这是本次最大的发现。

## 1. 桌面卡片机制（实测）

| 卡片 | 类型 | 提供者 |
|---|---|---|
| 时间 | AppWidget（2×1） | `com.xylink.timewidget/.TimeWidget`（`/data/app/MarlinTime.apk`） |
| 天气 | AppWidget（2×1） | `com.xylink.weatherwidget/.WeatherWidget`（原厂已被我们替换） |
| 电话 / 日程 / 消息中心 | AppWidget（1×1） | `vulture.app.home/vulture.appwidget.*` |
| 设置 / 文件夹 / 录像机 | 普通图标卡（1×1） | 数据库 `item_info` + PNG 图标 |

- 组件宿主：桌面自己就是 `hostId=1024`（`com.xylink.launcher/10024`）
- 桌面在 `/system/priv-app` 里，已拿到 `BIND_APPWIDGET`，**能自己分配并绑定组件**
- 桌面网格：单元格 220×280px，原点 (200,140)，4 列 × 2 行；卡片图规范 220×280 画布、实体 (12,17)-(207,272)、圆角 20

## 2. 时钟组件（含农历）

源码：`~/re-tools/t70l/tw/`　产物：`nemoclock.apk`（17KB）

完全复刻原厂布局（`RelativeLayout` + 3 个 `TextClock`），只多一个 `TextView` 放农历：

```xml
TextClock tv_time  96sp  hh:mm        marginLeft 20dp
TextClock tv_am    24sp  aa           紧贴时间右下
TextClock tv_date  24sp  MM月dd日 E    marginLeft 25dp / marginTop 28dp
TextView  tv_lunar 19sp  #99ffffff    日期右侧、基线对齐
```

显示效果：`11月01日 周日  丙午年农历九月廿三`

农历算法在 `Lunar.java`：内置 2020–2040 历表（`NYMD`/`BITS`/`LEAP` 三个 int 数组），
用「距正月初一的天数 → 逐月扣减」换算，闰月单独处理；干支纪年 `(year-4)%10 / %12`。

**验证**：与 `lunardate` 库交叉抽样 **500 天 0 误差**；春节 2024/2025/2026/2040、端午 2026-06-19、闰月 2033-12-22 全部正确。

更新时机：开机 / 每日 00:02 定时 / `updatePeriodMillis`；时间和日期由 `TextClock` 自己走，不需要我们推。

## 3. 天气组件

源码：`~/re-tools/t70l/wx3/`　产物：`nemowx3.apk`（37KB）

- 数据源：`http://t.weather.itboy.net/api/weather/city/<区县码>`
- 区县码规则：**市码末两位 `00` → `01`**；直辖市例外 → `省键+0100`
  - 辽阳 `101071000` → `101071001`；北京 `101010000` → `101010100`
  - 该接口**只认区县码**，市码会返回 403（这就是之前"城市很少"的真相）
- 城市库：34 省 / 350 个地级市，内置在 `Cities.java`
- 卡片布局：横向「大字号温度 + 右侧四行（天气/城市/高低温/空气质量）」
- **垂直对齐**：整块中心 y=231，与时钟块（156–306，中心 231）重合
  - 做法：`gravity=center_vertical` + `paddingTop=0dp` + `paddingBottom=98dp`
- 刷新策略（开机取不到数的坑）：
  1. 开机立刻取一次
  2. 失败则按 25/45/90/180/300 秒重试
  3. 监听 `CONNECTIVITY_CHANGE`，网络一就绪立刻补刷（20 秒去重）
  4. App 内刷新后直接把同一份数据推给桌面（`WeatherWidget.push`）

## 4. 踩过的坑

| 现象 | 原因 | 结论 |
|---|---|---|
| 卡片只有图标没有文字 | 用 `itemType=2`（图标卡）代替了 `itemType=4`（组件） | 要文字必须走组件 |
| 重启后组件显示 `--°` | 开机瞬间网络未就绪 | 加延时重试 + 网络变化监听 |
| 北京等直辖市取不到数据 | 省键+`00`+`00` 拼不出可用码 | 直辖市用 `省键+0100` |
| 桌面「设置」卡片消失 | 重启时原厂配置服务 `vulture.app.home` 崩溃，无法重建非组件卡片 | 从备份库恢复；根因待治 |
| 右键/滑动翻不到第二屏 | 该桌面分页只认真实触摸，adb 合成手势无效 | 需手指滑动验证 |
