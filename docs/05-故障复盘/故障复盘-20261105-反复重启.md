## 三、根因（两层，缺一不可）

### 3.1 第一层：`tv_restore.sh` 的 `kill -9` 死循环

```sh
# 罪证原文（已删除）
N=$(sqlite3 "$DB" "SELECT COUNT(*) FROM item_info WHERE title='看电视';")
case "$N" in
  0)
    sqlite3 "$DB" < /data/local/tmp/tv.sql      # ← ① 桌面持有库，必然 database is locked，写不进去
    P=$(ps | grep com.xylink.launcher | ...)
    [ -n "$P" ] && kill -9 $P                   # ← ② 不管写没写进去，一律杀桌面
    ;;
esac
```

三个错误叠加：

1. **用 `sqlite3` 直连库写数据** —— 桌面进程正持有 `_setting.db`，写入必然失败
2. **失败后仍然 `kill -9`** —— 桌面是 HOME 应用，系统 1 秒内自动拉起
3. **被 `do_loop` 每 10 秒调一次** —— 新桌面重建 `item_info` 又吞掉第三方条目 ⇒ 下一轮再补、再杀……

日志铁证（`launcher_guard.log`）：

```
11-05 17:35:06 修复完成 sig=...看电视:1:3:0...
11-05 17:35:16 布局偏离，开始修复
11-05 17:35:26 修复完成
11-05 17:35:36 布局偏离，开始修复     ← 每 10 秒一次，永远修不完
...
```

### 3.2 第二层：`warm_webview` 的 ANR

`boot_init.sh` 里这段：

```sh
warm_webview() {
    am start -a nemo.itent.action.activity.MyFullScreenWebActivity
    sleep 6
    input keyevent 4
}
```


```
10:20:08 预热 WebView
10:20:34 ===== boot_init 开始（uptime=9s）=====   ← 26 秒后重启
10:20:48 预热 WebView
10:21:15 ===== boot_init 开始（uptime=10s）=====   ← 又重启
```

**⚠️ 更坑的是：把 `warm_webview` 注释掉反而更糟** ——
因为 WebView 预热的作用是"在蓝牙被冻结之前先把 Chromium 初始化好"。
跳过它，后面只要有任何一个界面建 WebView（比如点「文件夹」），就必 ANR ⇒ 直接开机就重启。

## 四、救回来的关键动作（按顺序）

### 4.1 第一步：找 adbd —— 别只试 5555

```bash
nc -z -w 2 192.168.1.153 5555   # closed
nc -z -w 2 192.168.1.153 5656   # OPEN  ★ 就是这个
adb connect 192.168.1.153:5656
```

> **5656 的来源**：原厂看门狗 `com.vulture.watchdog` 的 `enablenetadb` 默认端口。
> 详见《故障复盘-开机崩溃.md》附录 A。
> **安全模式下 5555 一定关，5656 不一定关。顺序：5555 → 5656 → 全端口扫。**

### 4.2 第二步：掐掉开机自启（最保守但最有效）

```bash
adb shell "chmod 644 /data/local/tmp/boot_init.sh"
```

`install-recovery.sh` 的判据是 `if [ -x /data/local/tmp/boot_init.sh ]`，
去掉 x 位后开机就**什么都不跑**，设备回到纯原厂状态。
这是当时唯一能让它停止重启的办法。

> 注意：`chmod -x` 在这台设备上会报 `Bad mode`，必须用数字模式 `chmod 644`。

### 4.3 第三步：确认稳定

```bash
adb shell "cat /proc/uptime"    # 96 → 121 → 146 持续递增
adb shell "dumpsys window | grep mCurrentFocus"
# → com.xylink.launcher/com.xylink.launcher.app.LauncherActivity  ← 已退出安全模式
```

## 五、事后的正确修法（已落地）

### 5.1 `tv_restore.sh` 整条删除

「看电视」功能已整体下线：App 卸载、桌面条目删除、`tv.sql` / `tv_restore.sh` 清空。
`launcher_guard.sh` 的 `do_loop` 里那行调用也已删除，并在原位置留了注释说明原因。

### 5.2 铁律：常驻循环里禁止 kill HOME 应用

| 可以做 | 绝对不可以 |
|---|---|
| `content update/insert` 走桌面自己的 Provider | `sqlite3 DB < x.sql` 直连写库 |
| 修完等桌面自己刷新 | `kill -9 com.xylink.launcher` |
| 判据失败就记日志、下一轮再说 | 判据失败就"重启一下试试" |

**判据不是"杀了能不能恢复"，而是"这段代码有没有能力把设备拖进 bootloop"。**
`kill -9 HOME` + 每 10 秒一次 = **有**。所以它一开始就不该写。

## 六、设备重启后的恢复流程（手动，已实测）

当前 `boot_init.sh` 处于**停用状态**（`chmod 644`），开机后不会自动起任何东西。
需要手动恢复三个功能，顺序不能乱：

```bash
export PATH=$HOME/re-tools/platform-tools:$PATH
D=192.168.1.153:5555

# ① 指令执行 —— 必须先起 服务进程（指令执行 App 靠它发指令）

# ② 桌面布局（补回指令执行条目 + 修正坐标，走 ContentProvider，不杀进程）
adb -s $D shell "sh /data/local/tmp/launcher_guard.sh check"

# ③ 小智 —— 必须先踢掉会议 App 抢麦，顺序不能反
adb -s $D shell "am force-stop vulture.app.home"
adb -s $D shell "am force-stop com.lm.xiaoai"
adb -s $D shell "sleep 1; am startservice -n com.lm.xiaoai/.WakeService -a com.lm.xiaoai.WAKE"
```

### 6.1 抢麦验证（关键判据）

```bash
adb -s $D shell "dumpsys media.audio_flinger" | grep -A3 "Input thread.*active tracks"
# 期望：Client 那一行的 pid == com.lm.xiaoai 的 pid
# 如果 pid 是 vulture.app.home，说明它先抢到了 → 重做第 ③ 步

adb -s $D shell "logcat -d" | grep XiaoAiWake
# 期望看到：
#   监听已启动（v3 远场灵敏度版）
#   token 长度=153
#   开口 rms=xxx 底噪=xxx 阈值=xxx 声道=R 增益=x.x 流已开
```

> **重要**：`vulture.app.home` 被 watchdog 拉回来**没关系** ——
> 只要小智先拿到录音设备，它就抢不走（Android 4.4 只允许一个录音客户端，先到先得）。
> 所以关键是**启动顺序**，不是"永久禁止它运行"。

- **方向 A**：把 `warm_webview` 打开的页面换成本地 `about:blank` 或一个极简 HTML，不依赖厂商服务器
