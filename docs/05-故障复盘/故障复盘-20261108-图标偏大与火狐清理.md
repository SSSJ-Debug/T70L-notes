# 故障复盘：图标"总是大一圈" + 火狐/PLDroid 清理

> 2026-11-08 上午
> 用户主诉：① 桌面第二页的 Firefox 好像没用，删掉；② 听歌和抖音的图标还是偏大一圈，
> 为什么每做一个新软件图标就一定比原厂大，要彻底解决，以后也一样。

---

## 一、图标"大一圈"：真正的根因在第三层

### 1. 先排除的两个假设

| 假设 | 怎么验 | 结果 |
|---|---|---|
| 卡片画布尺寸不对 | 从 `_setting.db` 把 8 个 `icon` BLOB 拉下来，用 `check_icon.py` 量 | **全部 PASS**：画布 220×280、实体 180×240 @(20,20)、投影 196×256 |
| 卡片在屏幕上被放大 | `uiautomator dump` 抓每个图标的 View bounds | **8 个格子全是 220×280**：`[200,140]-[420,420]`、`[440,420]-[660,700]`… 一模一样 |
| 卡片实际渲染尺寸不同 | 截图逐像素横扫（卡片顶+120 行） | **8 张卡片宽度全是 180**（220~399、440~619、660~839…） |

三条都指向同一个结论：**卡片没有大，尺寸和位置都对。**

### 2. 换个角度：量卡片"里面"

把截图里 8 张卡片原样裁出来并排放在一起，肉眼立刻看出差别 ——
原厂图标中间那个图形很小，我们的几乎把卡片撑满了。

逐像素量图形 bbox（对卡片底色的色差判定，卡片坐标，卡片宽 180）：

| 图标 | 图形尺寸 | 占卡片宽 |
|---|---|---|
| 原厂 文件夹 | 64×57 | **36%** |
| 原厂 录像机 | 54×56 | **30%** |
| 原厂 设置 | 54×41 | **30%** |
| 翻车前 听歌 | 120×95 | **67%** |
| 翻车前 抖音 | 101×88 | **56%** |
| 翻车前 小智 | 113×92 | **63%** |

**差不多正好是原厂的 2 倍。** 这才是"大一圈"。

### 3. 机制原因（为什么会稳定复现）

`$HOME/re-tools/t70l/launcher_standard/mk_icon.py` 里：

```python
if (sw, sh) == (CANVAS_W, CANVAS_H):
    body = 直接取实体区，不缩放
else:
    body = cover_fit(src, sw, sh, BODY_W, BODY_H)   # ← 等比【覆盖】填满 180x240
```

`cover_fit` 是"覆盖"语义：任何小于 180×240 的 App logo 都会被**放大到撑满整张卡片**。
所以每次做新软件，只要 logo 不是提前做好的 220×280，就必然大一圈 —— 不是手感问题，
是工具默认行为问题。

### 4. 还有一个放大器：卡片底色太接近背景

听歌原来的卡片底色是 `#262F48`，桌面背景是 `#1E2030`，只差 `8/16/27`。
卡片边缘在深色背景上基本看不见 → 视觉上只剩中间那个大图形"浮"在背景里，
显得更大更糊。原厂看家虽然也是近黑卡片，但它比背景**更暗**（负对比），边界反而清楚。

**结论：卡片底色要么明显亮（品牌主色），要么明显暗（近黑），别卡在中间。**

## 二、修复：三个工具 + 一次重做

### 新增/改动

| 文件 | 作用 |
|---|---|
| **`mk_app_icon.py`（新）** | 新软件标准入口：`--logo` + `--bg` 一条命令出合规图标，logo 自动缩到最长边 64、居中在卡片内 y=64 |
| **`icon_content_fix.py`（新）** | 救已经偏大的老图标。`fit` 模式整体缩图形；`light` 模式只抠亮部图形换底色重贴 |
| **`check_icon.py`（改）** | 在原有三项之外，多输出「图形 XxY，占卡片宽 N%」，超 45% 直接提示"比原厂大" |

为什么 `light` 模式是必须的：抖音那种"卡片里套卡片"的图，
直接把内层黑方块缩到 64，方块里的 d 会一起缩成 20 多像素，糊成一团。
必须先按亮度把 d 抠出来，单独缩放，再贴到新卡片上。

### 三个图标的重做参数

```bash
icon_content_fix.py 听歌.png 新/听歌.png --mode light --bg 6E46E6 --thr 130
icon_content_fix.py 抖音.png 新/抖音.png --mode light --bg 14141C --thr 70
icon_content_fix.py 小智.png 新/小智.png --mode light --thr 170
```

### 结果

| 图标 | 图形（前 → 后） | 占卡片宽（前 → 后） |
|---|---|---|
| 听歌 | 120×95 → 54×64 | 67% → **30%** |
| 抖音 | 101×88 → 49×64 | 56% → **27%** |
| 小智 | 113×92 → 64×51 | 63% → **36%** |

对照原厂：文件夹 36%、录像机 30%、设置 30% —— 同一量级。

卡片底色也换掉了：
- 听歌 `#262F48`（几乎看不见）→ **`#6E46E6` 品牌紫**
- 抖音 `#262F48` → **`#14141C` 近黑**（负对比，像原厂看家）
- 小智 沿用原紫 `#6C4BDE`

## 四、火狐清理

### 它是什么

`org.mozilla.firefox` v68.0，`firstInstallTime = 2026-11-07 10:35:24` ——
做听歌软件时为了验 CDN/UA 装的临时浏览器，功能上没用。

### 清理过程中的两个坑

1. **只删桌面条目不卸包 → 桌面一重启就加回来。**
   第一次推完库启动桌面，`item_info` 里冒出一条 `PLDroid|1|3|1`。
   查包发现 `com.pili.pldroid.playerdemo` **一直还装着**：之前"删除 PLDroid"
   只删了图标，包没卸干净。
2. **桌面启动时会扫描已装应用并补条目**，所以顺序必须是：
   `pm uninstall` → 删两库的行 → 改 `launcher_guard.sh` 的 STD → 启动桌面。

### 最终状态

- `org.mozilla.firefox` 已卸载，`com.pili.pldroid.playerdemo` 已卸载
- 第二屏第二行补位：`小智(0,1)` `听歌(1,1)` `抖音(2,1)`
- `STD` 从 15 条改为 14 条，两库与守护脚本完全对齐
- 重启后 14 条保持，`OK 布局与标准一致`
