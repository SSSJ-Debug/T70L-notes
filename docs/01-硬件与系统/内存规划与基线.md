## 三、最大收益点：com.ainemo.speech.app（省 120MB）

### 3.1 它是什么

| 项 | 值 |
|---|---|
| 包名 | `com.ainemo.speech.app`（进程名 `nemo.speech.app`） |
| APK | `/data/app/com.ainemo.speech.app-1.apk` |
| 版本 | 1.0.0-19 |
| 本质 | 原厂 **MarlinSpeech 语音栈**：唤醒 + ASR + 语义理解 + TTS |
| 服务 | `XYWakeupService`、`AsrService`、`UnderstandService`、`com.mobvoi.speech.SpeechService` |
| 依赖方 | **`vulture.app.home`（桌面）bind 了前三个** |

### 3.2 为什么它吃 166MB

`dumpsys meminfo` 明细（优化前）：

```
  Native Heap       16       16        0        0   154992   154841      150
  Dalvik Heap     4271     4192        0        0     7224     6415      809
     .so mmap     9562     2732     6636        0
      Unknown   151822   151804        0        0
        TOTAL   170154   160464     8864        0   162216   161256      959
```

- **Native Heap 分配 151 MB，剩余仅 150 kB**（几乎撑满）
- 这部分在 `Unknown` 分类里体现为 **151804 kB Private Dirty**（真实物理占用，不可回收）
- 线程数 **50**，OpenSSL Sockets **30**

即：启动时把整套语音模型（唤醒 LSTM + ASR 声学模型 + 语言模型）一次性加载进 native 堆。

### 3.3 关键矛盾：它在空转

**麦克风被小智（`com.lm.xiaozhi`，PID 1180）占用**：

```
Input thread active tracks
Client Fmt Chn mask Session S   Server fCount
  1180   1 0000000C      21 6 0124E1C0  16384
```

Android 4.4 只允许一路 input 处于活动状态（见《语音控制-麦克风真相与接管方案.md》）：
**ainemo 拿不到麦 → 唤醒/ASR 全部无效 → 151MB 模型纯浪费。**

### 3.4 处置方式（已实测）

```bash
adb shell "am force-stop com.ainemo.speech.app"
```

效果（三次采样，间隔 40s）：

| 时点 | ainemo PSS | MemFree |
|---|---|---|
| 优化前 | 170154 kB | 197 MB |
| +5s | — | 354 MB |
| +60s | — | 318 MB |
| +2min | 50669 kB | 325 MB |
| +3min | 50812 kB | 327 MB |
| +4min | 50884 kB | 326 MB |

**稳定在 50 MB，不反弹。**

### 3.5 为什么不会反弹回 166MB

桌面会重新 bind 三个服务把进程拉起来（实测 PID 从 1034 → 15352），
**但因为麦克风仍被小智占着，唤醒引擎起不来，只加载基础组件（50MB），不加载 151MB 模型。**

### 3.6 风险与边界

| 风险 | 评估 |
|---|---|
| 桌面 bind 失败崩溃 | **未发生**。force-stop 后桌面 PID 745 一直在，前台正常 |
| 触发系统重启 | **未发生**。uptime 持续递增，`reboot_reason.info` 无新增 |
| 原厂语音功能 | **本来已失效**（拿不到麦），停掉不损失现有能力 |
| 重启后是否回到 166MB | **待验证**（未做重启测试，不写进自启脚本） |

> ⚠️ **铁律**：在这个方案经过「重启验证 + 语音功能回归测试」之前，**不要写进 `boot_svc.sh` 开机自启**。
> 依据《故障复盘-开机崩溃.md》§8.3 的强制流程。

## 六、给后续开发的硬约束

1. **自有 App 单进程 PSS 上限 40MB**（当前最大是小智 7.8MB，还有很大余量）
2. **不许开 `largeHeap`**，除非有实测数据证明必要
3. **图片缓存要封顶**：听歌的 `CoverLoader` 用 `LruCache`，容量按 `maxMemory/16` 且不超过 8MB
4. **WebView 类 App（抖音）单开一个进程**，退出即 `System.exit(0)`，不留常驻
5. **任何常驻服务必须能在 adb 里一句 `am force-stop` 干净退出**
6. **上线前必须跑**：`adb shell dumpsys meminfo <pkg>` 记录 TOTAL PSS 到本文档

## 七、复现命令

```bash
export PATH=$HOME/bin/platform-tools:$PATH
D=192.168.1.151:5555

# 全机基线
adb -s $D shell "dumpsys meminfo" > /tmp/mi.txt 2>&1
sed -n '/Total RAM/,/Lost RAM/p' /tmp/mi.txt
sed -n '/Total PSS by process/,/^$/p' /tmp/mi.txt

# 单进程
adb -s $D shell "dumpsys meminfo com.ainemo.speech.app" > /tmp/ai.txt 2>&1
sed -n '/MEMINFO in pid/,/^ *$/p' /tmp/ai.txt

# 谁占了麦克风
adb -s $D shell "dumpsys media.audio_flinger" > /tmp/af.txt 2>&1
grep -A3 "Input thread.*active tracks" /tmp/af.txt

# ⚠️ 注意：不要把 adb shell 的输出直接接管道（会 SIGPIPE → 看门狗重启）
#    见《故障复盘-20261107-命令行SIGPIPE触发看门狗.md》
```
