# T70L 自救方案 —— 彻底脱离厂商云（2026-11-04）

> 背景：T70L 厂商（Ainemo_Inc / xylink）官网已下线，但 CDN 下载服务器还活着。
> 本次恢复出厂纯属侥幸成功（厂商云没关）。为避免"厂商云一关机器就废"，必须建立自救能力。

### 2. 更新接口已完整分析（update_service APK 解析）
- **接口路径**：`/api/rest/version`、`/api/rest/crtt2`
- **查询参数**：`platform=<平台名>&sn=<序列号>`
- **平台名**：
  - `nemoos` = OTA 系统固件（当前最新 1226，但日期 2018 年，比设备旧）
  - `nemoawos` = aw 平台 OTA（octopus-f1 用的，853 版）
  - `nemohw` = 硬件资源包（2.19.0-3）
  - `nemorecovery` / `nemoawrecovery` = 恢复包（当前返回空）
  - `thirdapp` = 三方应用清单（需 sn）
- **三方应用查询**：`platform=thirdapp&sn=<序列号>` 返回 apkList

### 3. 设备当前版本 vs 云端
- 设备固件 = `ro.build.version.dev=573`（2019-04-23，**很新**）
- 云端 nemoos 最新 = 1226（2018-05，**比设备还旧**）
- **结论：设备已是最后一版出厂固件，无需"更新"，OS 已停产。**

## 三、自救能力清单（脱离厂商云后还能做什么）

1. **完整重刷 system 分区**：解压 OTA 包，把 system/ 下所有文件推回 /system，恢复所有原厂应用
2. **完整重刷 boot**：boot.img 可 dd 回 boot 分区
3. **重建 recovery**：recovery-from-boot.p + install-recovery.sh 可重建 recovery
4. **手动恢复三方应用**：用 `platform=thirdapp&sn=7Y1912128BD03B29` 拿完整清单，逐个下载 APK 存档

## 四、root 安全性结论

- root = 出厂 userdebug 固件自带：`/system/xbin/su`（setuid，75348字节）+ adbd 支持 root
- `ro.secure=1` 但 `ro.build.type=userdebug`，所以 adb shell 直接 uid=0
- OTA 包是 `eng_release`（工程版），理论上重刷后 root 仍保留
- **但绝不主动更新**：设备固件(573)已比云端(1226)新，更新=降级+变砖风险

## 五、★ 恢复出厂底层机制（已彻底分析，recovery last_log 全文分析）

**核心命令**：`/sbin/recovery --wipe_data --locale=zh_CN`

**分区表**（recovery 日志原文）：
```
/data      → /dev/block/by-name/UDISK   (ext4，注意！不是 mmcblk0p7，是 UDISK)
/system    → /dev/block/by-name/system  (ext4)
/cache     → /dev/block/by-name/cache   (ext4)
/recovery  → /dev/block/by-name/recovery
/misc      → /dev/block/by-name/misc
/boot      → /dev/block/by-name/boot
/env       → /dev/block/by-name/env
/bootloader→ /dev/block/by-name/bootloader (vfat)
```

**恢复出厂做了什么（日志原文）**：
```
Formatting /data...（格式化数据分区）
copy databk to data succeed（从出厂备份 databk 恢复预置数据）
```

**关键结论**：
1. **恢复出厂 = 纯本地操作，完全不依赖厂商云**：`recovery --wipe_data` 只做"格式化 /data + 从 databk 恢复出厂数据"
2. 蓝灯熄灭真相：恢复出厂走 recovery 的完整 wipe 流程，触发了硬件（AXP81x PMIC）的完整复位，把之前被搞乱的电源键状态机复位了
3. 三方应用重新下载才依赖云（但系统本身能本地恢复）

**触发方式**：
- `am broadcast -a android.intent.action.MASTER_CLEAR`（system_server 收到后写 misc 分区 + 重启进 recovery）
- 或直接写 misc 分区 boot command = "boot-recovery" + 重启
- 或 `reboot recovery` + `/sbin/recovery --wipe_data`
