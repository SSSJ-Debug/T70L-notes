## ⚡ 2026-11-08（下午·最新）看家 15→20fps + 图标"大一圈"第三层根因

> 用户：① 看家预览再流畅点，画质可以让，但别吃 CPU/内存，抓拍还要高清；
> ② 听歌/抖音图标**又**大了一圈，为什么每做一个新软件就大，彻底解决。

### 一、看家：真凶是相机 HAL 的离散帧率档位，不是算法

`Camera.Parameters.flatten()` 里躺着决定性的一行：

```
preview-frame-rate-values=15,30        ← 离散档位只有 15 / 30
preview-frame-rate=15                  ← 出厂默认钉在 15
preview-size-values=1920x1080          ← 只有一档，没法降分辨率换帧率
```

**之前"15fps 是物理上限"的结论是错的** —— 那是 HAL 档位没被改。
试过但**无效**的三条（别再试）：`setPreviewFpsRange(30000,60000)`、`(30000,30000)`、曝光补偿压到 -6。

唯一有效写法（两条一起写，顺序不能反）：

```java
p.setPreviewFpsRange(30000, 30000);
p.setPreviewFrameRate(30);      // 这条最关键，会被上一条覆盖，必须后写
```

| 指标 | 前 | 后 |
|---|---|---|
| 相机出帧 | 14~15fps | **17~25fps**（界面显示 20fps） |
| 预览/绘制 | 14fps | **17~25fps**，drop 0~1 |
| 帧到屏延迟 | 未测 | **18~32ms** |
| 进程 CPU | 8% | 10% |
| PSS | 25.5MB | **25.4MB** |
| 抓拍 | 1080p JPEG q78 | **一行没动** |

另加**前后台自适应**：界面前台 30 档（流畅优先），息屏值守 15 档（曝光翻倍，夜里抓拍更清楚）。
注意这颗 HAL **运行中只能升档不能降档**，降档要重开预览 —— 我们没做，实测 30 档下抓拍照片亮度仍正常（196KB / 1080p）。

### 二、图标"大一圈"的第三层根因：桌面会把 APK 图标重画一遍

冷启动 / 装包后，桌面会把第三方应用条目**整行重建**：
把 APK 的 launcher 图标缩到**宽 120**，贴到桌面自己的卡片上，再整张存成**满铺 220×280** 的 BLOB。

我们做的 220×280（含 180×240 卡片）被这么一缩 → 变成"卡片里套卡片"，图形占 **54~56%** → 又是"大一圈"。

**所以只修数据库治不住：下一次 `pm install` 必然重画。** 这是前两轮（画布层、卡片内容层）都没碰到的第三层。

修复：`launcher_guard.sh` 新增 `sync_icons()` —— 14 条标准条目逐条与模板库做**字节比对**，
不一致就用模板覆盖；触发点「检测到包变化立即」+「每 60 秒巡检」+「restore_layout」。

同时把这一轮超标的四个图标归一（图形宽统一 ≤64 = 卡片宽 36%）：

| 图标 | 前 → 后 |
|---|---|
| 看家 | 58% → **36%**（APK 内置 `ic_guard.png` 一起换了） |
| 看电视 | 67% → **36%** |
| 扩展屏 | 76% → **36%** |
| 哔哩哔哩 | 43% → **31%** |

`build_guard.sh` 新增图标门禁：`check_icon.py` 报「比原厂大」就直接拒绝打包。

实测日志：`图标偏离模板 2 个 → 按模板复位`（装 guard 触发）、
冷重启后 `听歌/扩展屏/抖音 条目缺失，从模板补回` → 12 个图标全部 25~36%。

> ⚠️ 桌面界面有内存缓存：守护把库修好了，但**屏幕要等桌面进程重进一次**才变。
> 需要时执行一次 `am force-stop com.xylink.launcher` + `input keyevent 3`（只做一次，别循环）。

`cam_guard` v2：0.4s 轮询、只在相机真被占时才 force-stop、看家 400ms 重试、open 前先递预请求；
**拿到相机之后**才 `am startservice PeripheralService`，把电话 widget + 呼吸灯拉回来（实测记录数 7，桌面正常）。

### ⚠️ 我自己搞出来的两次重启（必读铁律）

调试时设备重启 2 次：`grep crash / sh crash more than 5 times in 180s`。
原因是设备侧管道踩 SIGPIPE：`ps | grep | awk | head -1`（awk/head 根本没有）、
以及 `sh cam_guard.sh status | busybox grep -q running`（`-q` 提前退出，`sh` 写管道吃 SIGPIPE，15 秒一次）。

**铁律**：设备侧禁止 `cmd | grep -q`、`cmd | head -1`；一律 `命令 > 文件`，再 `busybox awk` 读文件。
`cam_guard.sh` / `mic_keeper.sh` 已全部整改，并新增 `cam_guard.sh check`（只回退出码）。

## ⚡ 2026-11-08（上午 09:45）原厂抢麦根治 + 长聊隔离

> 用户两条诉求：① 原厂 App 抢麦能不能删掉；② 长聊天老是自己开，必须暗语才进。

### 结论一：原厂 `vulture.app.home` 不能删，已用官方开关关掉它的语音

它是 **Nemo / 小鱼在家** 整机业务壳（`/data/app/`），提供视频通话、通讯录、留言、消息中心、
系统设置、桌面 widget，以及 **`PeripheralService`（呼吸灯 / 电话 widget 依赖）**。
同族还有 `vulture.watchdog`（system 权限，会 rebootSystem）—— 删包可能直接变成开机重启循环。

**做法：不删、不禁包，只改一个官方配置项。**

```java
// SpeechModule.java
this.isEnable = VoiceAssitantSettting.parse(b.r().getVoiceAssitantSetting()).enableVoiceAssitant;
if (this.isEnable) { mVoiceProcessor.startSpeechUtils(); ... }   // 只有这里才开麦
```

键名 `VoiceAssitantSetting` 在 `local_config.xml`，**原机根本没这个键 → 默认 true → 出厂常开**。
写入 `{"enableVoiceAssitant":false,...}` 后：
- 原厂语音界面打开 + 按住说话，录音轨仍然 `S=0`，`No active record client`，**抢不走**
- 冷重启后保持，小智开机 64s 即 `S=6` 正常录音
- `PeripheralService` / widget / 桌面全部保活，未触发看门狗
- `setVoiceAssitantSetting()` 全包无调用者 → 云端不会覆盖

回滚：`cp /data/local/tmp/local_config.xml.orig ...`（详见复盘文档）。

### 结论二：长聊隔离

| 改动 | 说明 |
|---|---|
| `Prefs.continuous` 默认 `true` → **`false`** | 以前喊一次「小智」后 25 秒内所有话都被接走，这是"自己开长聊"的元凶 |
| `XzService.chatIntent()` 重写 | 旧版「人称+聊」就进（"我们聊聊天气"也进）；新版只认完整词组（聊聊天/陪我聊/聊会儿…），ASR 的「疗/辽」先归一化再匹配 |

实测：`小智，我们聊聊今天天气怎么样` → 不进畅聊；`小智我们聊聊天吧` → 进；
`小智开灯` → 执行 + 畅聊一并落地；`今天天气怎么样`（无唤醒词）→ 不理。

### 使用规则

- 开灯/关灯：**「小智开灯」**（必带小智，说完即回待命，永不进聊天）
- 问一句：**「小智，现在几点」**（答完就回待命）
- 长聊：**「小智，我们聊聊天」**（唯一入口，5 分钟静默自动退出，说「小智不聊了」退出）

## ⚡ 2026-11-08 更新：小智「隔夜失联」根治

> 用户主诉：过几个小时不用（比如夜里关灯后到早上），喊"小智小智"彻底没反应。
> **要求：只要 T70 开机，24 小时任何时刻"小智开灯/小智关灯"必须可用。**

### 根因（两条，都是"静默失效"）

1. **麦克风被原厂独占**：`dumpsys media.audio_flinger` 现场显示
   `804 (vulture.app.home) Session 11 S=6` 在录，而小智的输入线程是空的。
   Android 4.4 全机只有一路录音通道，先到先得、抢到即独占。
   更糟的是小智 `openRec()` 把 `startRecording()` 失败（`status -38`）当成功，
   无条件打「麦克风就绪」→ 87 分钟里 1737 次假成功，用户听到的就是"死了"。
2. **WebSocket 从不发心跳**：路由器 NAT 空闲几分钟回收 TCP 映射，
   连接静默死掉但本地 `open` 仍为 true，音频发进黑洞 —— 「早上第一句」必踩空。

### 修复

| 位置 | 改动 |
|---|---|
| `XzService.openRec()` | 真判定 `getRecordingState()` + 首读校验；失败 release 并报「被占用」，不再伪装成功 |
| `XzService.loopImpl()` | 失败重试 500ms → 3 秒退避；内层连续 20 次读不到 200ms 内拆掉重开 |
| `XzService.startLinkKeeper()` + `XzClient.sendPing()` | 每 40 秒主动 ping 保 NAT；空闲 240 秒且非对话态则判定假死并重建 |
| **`/data/local/tmp/mic_keeper.sh`** | 常驻守护：每 15 秒查录音持有者，小智没麦就踢 vulture（并立刻拉起 PeripheralService 保 widget/呼吸灯）、拉起/重启小智；每小时动手上限 6 次 |

`mic_keeper.sh` 已挂进 `boot_svc.sh` 的 `start_daemons()`，开机自启。

### 实测

- 重启后 `boot_svc.log`：`麦克风归属处理完毕：小智：正在录音`（uptime 62s）
- 小智被杀：`09:08:49 小智不在 → 拉起` → `09:09:03 恢复成功`（14 秒）
- `force-stop vulture.app.home` 后 6 秒小智拿到 session，云端 ASR 正常返回文字
- `launcher_guard.sh check` → `OK 布局与标准一致`；未触发看门狗

完整复盘见 **`故障复盘-20261108-小智隔夜失联.md`**。

### 三条硬结论

1. **反复重启的机制找到了**：原厂 `NemoWatchdog`（`/system/app/NemoWatchdog.apk`，system 身份）
   的规则是「**任何进程 180 秒内崩 ≥5 次 → rebootSystem**」。
   历史 67 次重启的账本在 **`/cache/watchdog/reboot_reason.info`**，这是最权威的重启原因来源：
   ```
   36 app_process crash     ← 11-01 那次"反复重启到安全模式"
   20 ps crash              ← 全都是 ``adb shell ps | head`` 造成的
    6 mediaserver crashed   ← 真系统级，未解
    2 ls crash / 2 grep crash ← 同上，命令行问题
    1 com.lm.guard crash    ← 我们自己的守护 App，已随版本更新消失
   ```
   **67 次里有 24 次（36%）是自己的命令行用法造成的，不是设备故障。**

2. **内存大头不是我们的 App**：`com.ainemo.speech.app`（原厂 MarlinSpeech 语音栈）占 **170MB PSS**
   （Native Heap 分配 151MB、50 线程）。因为麦克风被小智占着，它**根本录不到音，纯空转**。
   `am force-stop` 后稳定在 50MB，**省 120MB**：
   ```
   Free RAM 521MB → 643MB      MemFree 197MB → 326MB      Used pss 421MB → 301MB
   ```
   自有 App 全部很小：小智 7.8MB、guard 2.8MB、抖音 14MB、Firefox 8.5MB。

3. **抖音只能做原生**：Chrome33 跑不了 2026 年的抖音网页版（缺 CSP nonce、缺现代 JS 语法），
   且本机**没有独立 WebView 包**（内核编在 framework 里，升不了）。
   已交付原生版：**36.4KB / 14MB 内存**，B 站热门流 + 抖音式上下滑交互。源码 `核心资产/源码/12-抖音/`。

### 双屏互联：硬件不支持（已验证，别再试）

| 方向 | 实测 | 结论 |
|---|---|---|
| T70L → Mac | `screencap -p` **2.9~3.0 秒/帧**（0.3fps） | 不可用 |
| T70L → Mac（读 fb0） | `dd` 已 0.42s/帧，加传输 1~2fps | 不可用 |
| Mac → T70L | `screencapture` 0.5s（4K）+ 传输显示 ≈ 1s/帧 | 只能当信息屏 |
| HDMI 采集卡 | **本机屏幕是 MIPI 直连 LCD，无 HDMI 输出口** | 不存在 |

根因：Android 4.4 没有 `MediaProjection`（5.0+），`screenrecord` 不支持 `--output-format=h264`（5.0+），
`adb exec-out` 在本机返回空。**软件投屏无解，只能上硬件（便携显示器 / iPad Sidecar）。**
