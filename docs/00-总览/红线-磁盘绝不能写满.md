# 红线 · 磁盘绝不能写满

> 这条红线不是风格建议，是**已经用一台真机换来的**。
> 2026-11-23，一台 T70L 的 `/data` 被写到 0 空闲块，卡在开机第一屏进不去桌面，最后只能格式化救回。

## 一、事故长什么样

| 指标 | 出事时 |
|---|---|
| `/data` 可用 | **0 块** |
| `/data/log` 体积 | **832 MB** |
| 崩溃转储 `/data/log/pending` | **326 份 × 2.9 MB ≈ 946 MB** |
| 现象 | 开机第一屏（Logo）卡死，ADB 连不上，只能 recovery 格式化 |

两个写盘元凶：

1. **`/init.rc` 里的两个 init 服务**：`nemodlogger` / `nemorlogger`，
   都是 `logcat -r10240 -n 30 -f /data/log/logcat_full.log`
   → 单服务上限 300 MB，两个近 600 MB，**永不停止**。
2. **脚本日志无上限追加**：`>> $LOG` 写一辈子。

放大器：任何**崩溃循环**。脚本每 3 秒崩一次，每次产生约 2.9 MB 崩溃转储，
一小时就是 3 GB —— 磁盘撑不过一个下午。

## 二、四条硬规则

### 规则 1 · 每个 `log()` 必须封顶

```sh
# ❌ 绝对不要这样
log() { echo "$($BB date) $*" >> $LOG; }

# ✅ 必须这样（超 256KB 只留最后 128KB）
_capn=0
_caplog() {
    _capn=$((_capn + 1))
    [ $((_capn % 50)) -ne 0 ] && return 0
    _s=$($BB wc -c < "$LOG" 2>/dev/null)
    [ -z "$_s" ] && return 0
    [ "$_s" -gt 262144 ] || return 0
    $BB tail -c 131072 "$LOG" > "$LOG.t" 2>/dev/null && $BB mv -f "$LOG.t" "$LOG"
}
log() { echo "$($BB date '+%m-%d %H:%M:%S') $*" >> $LOG; _caplog; }
```

### 规则 2 · 常驻循环里不许出现「崩溃循环」

- 循环体里的程序如果每轮都崩，**先停脚本**，别让它一直重试。
- 不要在循环里 `kill -9` 桌面 / HOME 应用 —— 会被系统秒拉起，每 10 秒一条崩溃转储。
- 循环里别用 `grep -q` / `head` / `ps` 这类会提前关管道的东西，SIGPIPE 会被看门狗判成 crash
  （见 `docs/05-故障复盘/故障复盘-20261107-命令行SIGPIPE触发看门狗.md`）。

### 规则 3 · 关掉原厂 logcat 落盘服务

```sh
setprop ctl.stop nemodlogger
setprop ctl.stop nemorlogger
rm -f /data/log/logcat_full.log*
```

### 规则 4 · 必须有磁盘总闸兜底

```sh
sh 源码/17-磁盘守护/02-disk_sentinel.sh &   # 每 60 秒：关 logcat 落盘 + 白名单日志封顶
sh 源码/17-磁盘守护/01-disk_guard.sh --check # 三级水位体检
```

三级水位：`< 512MB` 清缓存截断日志 / `< 300MB` 删采集文件 / `< 150MB` 删可疑大文件。

## 三、开工前 60 秒体检

```sh
df /data                                  # 可用 < 1GB 就别开工
du -sk /data/log                          # > 100MB 就是有东西在写

sh 源码/17-磁盘守护/01-disk_guard.sh --check
```
