# T70L 电话功能 · 终局结论

> 时间：2026-11-04 20:10
> 设备：T70L / Android 4.4.4 / L710 模块 / 电信 46011
> 结论一句话：**电话功能没坏，是这台设备绑定的云账号 PSTN 外呼额度 = 0 分钟。**

---

## 一、三层证据（全部为本次实测，非推测）

### 第 1 层 · App 层：拨号盘根本不经过 SIM 卡

分析 `vulture.app.home`（19MB，桌面+电话同一进程）得到的事实：

| 事实 | 证据 |
|---|---|
| 无任何 Android 电话调用 | 全包搜 `android.intent.action.CALL` / `ITelephony` / `TelephonyManager` / `tel:` → **零命中** |
| 有完整云端 PSTN 体系 | `CallMode_Tel`、`DeviceType.TEL(99)`、`TelRecentCallItem`、`getPSTNRecentCall()`、`dial_panel_free_call_balance`、`getPhoneAvailableTime()` |
| 拨号盘数字 → 云端号码翻译 | `GET https://cloud.xylink.com/api/rest/v4/nemoPhoneCallUrl?number=…` → 返回 `callUrl=+86-01010000@TEL, numberType=PSTN` |
| 呼叫由云端 SIP 网关发起 | `SIP INVITE  from: 351376162@HARD  to: +86-01010000@TEL`（OPUS/48000，RTP/SAVP） |

**所以"打手机号"这件事，在这台机器上是"让云端网关替你拨一个 PSTN 电话"。**

### 第 2 层 · 云端层：额度就是 0（本次新增的关键证据）

从设备数据库 `nemo_data.db → loginresponse` 取出真实凭证：

```
nemoNumber  = 179411
serverUrl   = cloud.xylink.com
securityKey = be183519…（脱敏）
```

**实时查询云端额度接口**（`Uris.java:71` → `PATH_PHONE_AVAILABLE_TIME = /api/rest/v3/pstn/availabletime`）：

```
GET https://cloud.xylink.com/api/rest/v3/pstn/availabletime?securityKey=<真实key>
→ HTTP 200   0
```

**对照实验（证明这个 0 是真数据，不是接口兜底值）：**

| securityKey | 结果 |
|---|---|
| 真实 key | `HTTP 200` → **`0`** |
| 伪造 key | `HTTP 401 Unauthorized` |
| 空 key | `HTTP 401 Unauthorized` |

设备侧还有两条独立印证：

- `shared_prefs/本月免费时长.xml` → `<long name="本月免费时长" value="0" />`
- `shared_prefs/local_config.xml` → `UIDisplayCustomization` 里 **`"showPstnTime":"false"`**
  → 官方把"可用时长"在界面上**主动隐藏**了。所以自始至终你看不到余额，也看不到"余额不足"的提示。

**这条解释了两件怪事：**

1. 为什么点了没反应 —— 云端 380ms 就拆线，返回 `reason:9999`，App 的枚举表里没有 9999，统一归为 `UNKNOWN_ERROR`，播放一句"未知错误"的语音，然后 `NemoCallActivity.finish()` 直接关界面。
2. 为什么通讯录里那么多手机号 —— 那些是企业云通讯录同步下来的联系人，号码本身没问题，能"拨出去"，只是**出不了网**。

### 第 3 层 · 硬件层：模块在语音域里压根没注册

AT 口（`/dev/ttyUSB0`）实测：

```
AT+COPS?    → +COPS: 0,0,"CHN-CT",7      ← act=7 = E-UTRAN（仅 LTE）
AT+CREG?    → +CREG: 2,4                 ← stat=4 = unknown，CS 域（语音域）未注册
AT+CEREG?   → +CEREG: 2,1,"0BAF","00CE3B32",7   ← LTE 分组域已注册，正常
AT+CFUN?    → +CFUN: 1,0                 ← 全功能模式
AT+GTRAT?   → +GTRAT: 3                  ← 制式锁定（3 = LTE 优先/锁定）
AT+CGDCONT? → 1,"IP","CTNET",…           ← 只有数据 APN，无 IMS APN
AT+CLCC     → OK（无任何呼叫）
```

`+CREG: 2,4` 是硬结论：**模块没有、也无法注册到任何电路域语音网络。**

原因不是它"坏了"，是三条同时成立：

| 条件 | 电信 46011 的实际情况 |
|---|---|
| CDMA / 1xRTT | 已退网，且 L710 规格里**没有 CDMA** |
| WCDMA / GSM（CS 回落目标） | 电信卡没有这张网 |
| VoLTE | L710 **不支持**，且 `AT+CGDCONT` 里没有 `IMS` APN |

换移动/联通卡能不能救？理论上模块有 WCDMA B1/B8 + GSM 900/1800，CS 域可能注册得上。但还有两道闸：`config_voice_capable=false`（框架层禁语音）+ 系统里没有任何走 RIL 的拨号器。**换卡只是必要不充分条件。**

### 第 4 层 · 历史记录：这机器从来没打通过一次

`nemo_data.db → telrecentcallitem` 全表：

```
共 1 条 | 号码 10000 | deviceType=TEL | callDirection=0 | duration=0
```

**整机历史上只有我们测试的那一通，时长 0 秒。** 不是"以前能打现在不能"，是从未成功。

## 二、那为什么拨号盘要写"云会议号、终端号或手机号"？

因为这是**三合一入口**，对应三种完全不同的目标类型（`DeviceType`）：

| 输入 | 类型 | 实际动作 |
|---|---|---|
| 云会议号 | `CONFERENCE(97)` | 进云端会议室（免费，走企业套餐） |
| 终端号 | `HARD(2)` / `SOFT(1)` | 点对点视频呼叫另一台终端（免费） |
| 手机号 | **`TEL(99)`** | **PSTN 外呼（按分钟计费，就是缺额度的这项）** |

三合一设计本身很合理 —— 会议、终端互呼都是免费的、都正常；只有第三项要钱。厂商把额度显示隐藏了（`showPstnTime:false`），中移这个定制批次大概率根本没给账号配 PSTN 套餐，于是就出现了"看起来什么都能拨，实际只有手机号拨不出去，还不告诉你为什么"。

## 三、四条路 · 成本与风险

### 路 A：给云账号加 PSTN 额度（官方正路）

| 项 | 内容 |
|---|---|
| 找谁 | 小鱼易连（xylink，中移云视讯的技术方）客服 / 中移客户经理 |
| 报什么 | 设备号 `179411`，服务器 `cloud.xylink.com`，SN 见系统信息 |
| 说什么 | "这台终端的 PSTN 外呼额度是 0，`/pstn/availabletime` 返回 0，需要开通外呼套餐" |
| 前提 | 需要有该企业租户的管理员权限，或让管理员在后台开 |
| 成本 | 按分钟计费（通常 0.1~0.3 元/分钟，各地套餐不同） |
| 成功率 | 高 —— 只要有人肯开权限。这是唯一能让**原生拨号盘**工作的办法 |

### 路 B：装第三方 SIP 客户端（绕开厂商云，不求人）

| 项 | 内容 |
|---|---|
| 可行性 | 设备能装 APK（之前装过天气 widget，已验证），Android 4.4.4 支持 Linphone 3.x / CSipSimple |
| 需要什么 | 一个 SIP 账号 |
| 打 SIP 号 | 免费（`sip.linphone.org` 可免费注册，两个客户端互打不花钱） |
| 打 10000 这种 PSTN | **仍然要买 SIP 中继**（运营商/云厂商的 SIP trunk，月租+话费），绕不开钱 |
| 风险 | 零（独立 App，不动系统） |
| 体验 | 多一个 App，不能和桌面拨号盘融合 |

### 路 C：改造成"真手机"（换移动/联通卡 + 开语音栈）

| 步骤 | 难度/风险 |
|---|---|
| 换移动或联通卡 | 简单，但要额外一张卡 |
| `AT+GTRAT=0` 放开制式 | 低（但电信卡下无意义，必须换卡后才试） |
| 改 `config_voice_capable=true`（framework-res） | **中高风险**，改错可能开不了机 |
| 装系统 Phone.apk | 中（4.4 的拨号器要匹配 RIL 版本） |
| L710 是否有 PCM 音频通路 | **未知** —— 数据模块常常把音频通道焊死，这是最大不确定项 |

**结论：技术上有可能，但要动 framework，且收益不确定。按你"不能变砖"的底线，我不建议先动这条。**

### 路 D：接管云端，让原生拨号盘指向自建 SIP（最漂亮，工程量最大）

原理：设备是标准 SIP 终端，只认云端下发的 `callUrl`。

```
1. 改 /system/etc/hosts：cloud.xylink.com → 自建服务器
2. 自建 HTTPS 服务，复刻 /api/rest/v4/nemoPhoneCallUrl 响应
3. 返回 callUrl = 你自建 Asterisk/FreeSWITCH 的地址
4. 拨号盘、通讯录、通话记录全部原生保留，只是通话走你自己的服务器
```

| 项 | 内容 |
|---|---|
| 拦路虎 | Android 4.4 会校验 HTTPS 证书 → 需把自签 CA 塞进 `/system/etc/security/cacerts/`（root 可做） |
| 还需要 | 一台有公网 IP 的服务器跑 Asterisk |
| 打 PSTN | 依然要 SIP 中继，依然要钱 |
| 风险 | 中 —— 改 hosts 影响登录流程，登不上会让桌面异常，必须做好整机备份+回滚 |

**这条路适合"我要把它彻底变成我自己的设备"，不适合"我只想打通 10000 试试"。**

## 四、建议动作（按性价比排序）

1. **先花 3 分钟打个电话**（零成本，立刻有答案）
   小鱼易连客服，报设备号 `179411`，问："这台终端的 PSTN 外呼额度是 0，能不能开？多少钱一分钟？"
   一句话就能判断路 A 通不通。

2. **如果想"不花钱先验证电话功能真的能用"**
   走路 B：装 Linphone + 免费 SIP 账号，两个客户端互打。这能证明"扬声器/麦克风/编解码/网络"整条音频链是好的，只是没有 PSTN 出口。

3. **路 C / 路 D 先不动。** 前者可能白折腾还担风险，后者等你确认"确实要用它打电话"再上。

## 五、一句话回答你最初的三个疑问

| 你的疑问 | 答案 |
|---|---|
| 插了电信卡为什么打不出去？ | 这张卡只提供 4G 数据。语音不走它，走云端 PSTN；而云端额度是 0。 |
| 是不是模块/系统不支持？ | 模块确实不支持电信语音（无 CDMA/VoLTE，`+CREG:2,4`），但**这不是打不出去的直接原因**——App 根本没试过用 SIM 打电话。 |
| 拨号盘写手机号、通讯录有手机号，说明以前打过？ | 通讯录是企业云通讯录同步的。拨号盘是"会议号/终端号/手机号"三合一，前两种免费且一直能用，第三种要 PSTN 额度。整机历史通话记录只有 1 条、时长 0 秒——**从未打通过**。 |

