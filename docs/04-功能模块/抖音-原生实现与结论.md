## 一、为什么不是「抖音网页版套壳」

原本的方案是 WebView 套 `www.douyin.com`，实测**三层堵死**：

### 1.1 内核跑不了现代 JS

```
D/Douyin: js: Uncaught SyntaxError: Use of future reserved word in strict mode @1
```

Chrome 33（2014 年 V8）不认识现代语法。polyfill 能补 API（`ResizeObserver`/`fetch`/`Set`），
**补不了语法**。这条路没有救。

### 1.2 CSP 拒绝所有内联脚本

```
Refused to execute inline script because it violates the following Content Security Policy directive:
"script-src 'report-sample' 'strict-dynamic' 'nonce-KhMpiXewGkZ_fxYKP3f7e' 'wasm-unsafe-eval'
 'unsafe-eval' 'self' *.bytedance.com ..."
```

抖音用 **CSP nonce**。nonce 是 CSP Level 2，**Chrome 36 才支持**，33 不认识 → 全部拒绝 → React 起不来 → 黑屏。

### 1.3 内核无法升级

```bash
$ adb shell "pm list packages -f" | grep -i webview
（空）
$ adb shell "dumpsys webviewupdate"
Can't find service: webviewupdate
```

**这台设备没有独立 WebView 包**，Chromium 33 是编在 framework 里的（Android 4.4 AOSP 做法）。
Android 5.0+ 才能通过装 APK 换内核。**升级路径不存在。**

### 1.4 抖音 API 也拿不到

```
首页 HTML: 72914 字节，内容是 _$jsvmprt 的 JS 虚拟机保护壳，无服务端数据
热榜接口: {"status_code":0,"aweme_list":[],...}   ← 返回空
```

所有 `/aweme/v1/web/*` 接口都要 `a_bogus`/`Argus` 签名，纯 Java 复现不现实。

**结论：真抖音在这台机器上没有任何可行路径。** 用户确认改做「刷抖音的样子」。

## 二、实现架构

```
com.lm.douyin/
├── MainActivity.java   界面 + 手势 + 播放器（本 App 的核心）
├── Feed.java           B站数据源：热门列表 + MP4 直链
├── Net.java            手写 HTTP 客户端（强制 IPv4 + TLS）★从听歌App复用
├── StreamProxy.java    本地 http 代理，把 https 视频喂给 MediaPlayer ★复用
└── Http.java           UA / SSLSocketFactory ★复用
```

复用的三个类在听歌 App 里已经打通过，坑都踩过了（见《11-听歌-实现逻辑.md》）。

### 2.1 为什么必须走本地代理

B 站给的 MP4 直链是 **https**：

```
https://cn-lnsy-cu-01-01.bilivideo.com/upgcxcode/54/03/43399120354/43399120354-1-16.mp4?...
```

Android 4.4 的 NuPlayer 没有可用 TLS，`setDataSource(https)` 直接 `error -1004`。
所以：**应用内 Java 拉 https → 本地 `http://127.0.0.1:18778` 喂给 MediaPlayer**。

端口用 **18778**（听歌占 18777，避免冲突）。

代理支持 **Range 透传**，播放器 seek 可拖动；每连接一线程，用完即关。

### 2.2 数据源（B 站，免签名）

| 用途 | 接口 |
|---|---|
| 热门列表 | `api.bilibili.com/x/web-interface/popular?ps=20&pn=N` |
| 播放地址 | `api.bilibili.com/x/player/playurl?bvid=&cid=&fnval=1&qn=64` |

两个关键点：

1. **热门列表本身就带 `cid`**，不必再请求 `view` 接口，省一次往返。
2. **`fnval=1` 要「整段 MP4」而不是 DASH 分轨**。4.4 的播放器解不了 DASH。
3. **`qn=64` 是未登录能达到的最高画质**（720P，10MB 左右）。`qn=80` 会被降回 64。

### 2.3 交互（对齐抖音）

| 操作 | 行为 |
|---|---|
| 上滑 | 下一条 |
| 下滑 | 上一条 |
| 单击 | 暂停 / 继续 |
| 播完 | 自动下一条 |
| 右侧 ♥ / 弹 / ↗ | 示意（弹提示，不接真实接口） |

右侧操作栏：作者头像圆 + 点赞数 + 弹幕数 + 分享，底部 `@作者` + 标题 + `播放量 · 时长 · 分辨率`，
右上角 `当前/总数`。顶部提示 **8 秒后自动隐藏**，不挡画面。

### 2.4 内存纪律

| 措施 | 说明 |
|---|---|
| **无 `largeHeap`** | Manifest 里已删除，实测没必要 |
| 单播放器 | 切条必 `release()`，同一时刻只有一个 MediaPlayer |
| 列表封顶 60 条 | 超出丢弃最早的，`PAGE_KEEP` 控制 |
| 预取只解析不下载 | 提前拿 `playurl`，不预载视频 |
| 文字加 `setShadowLayer` | 亮背景上也能看清，不额外占内存 |

## 三、实测性能

| 指标 | 数值 |
|---|---|
| **APK 体积** | **36.4 KB**（37335 字节） |
| **运行 PSS** | **13.7 ~ 15.6 MB** |
| RSS | 34.6 ~ 35.5 MB |
| 720P 单条 | 约 5~10 MB MP4，代理完整送完 |
| 连续切换 | 5 次上滑稳定，无崩溃无重启 |
| 视频适配 | 按比例铺满：横屏视频铺满全屏，竖屏视频高度铺满、左右留黑 |

对比：原厂 `com.ainemo.speech.app` 占 170MB，本 App 只占 14MB。**符合「小而美」。**

## 四、已知限制（诚实记录）

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| 1 | 序号会跳号（如 3→5） | 个别视频 `playurl` 返回 `code=-404`（番剧/付费/已删） | 已自动跳过并提示 |
| 2 | 部分视频很大（见过 125MB） | B 站热门里有长视频/番剧 | 流式播放不占内存，但耗流量 |
| 3 | 内容不是抖音 | 真抖音无可行路径（见第一节） | 用户已确认接受 |
| 4 | 右侧点赞/评论不接真实数据 | 需登录态 + 签名，本版只做示意 | 后续可选 |
| 5 | 没有封面预览 | 切换时是黑底 + "加载中…" | 预取已把等待压到 1 秒内 |

## 五、构建与部署

```bash
cd "$HOME/Desktop/中移T70L/核心资产/源码/12-抖音"
./build_douyin.sh
adb -s 192.168.1.151:5555 install -r douyin.apk
adb -s 192.168.1.151:5555 shell "am start -n com.lm.douyin/.MainActivity"
```

工具链：`aapt` → `javac -source 8 -target 8`（bootclasspath=`android-19.jar`）→ `d8 --min-api 19`
→ `zipalign` → `apksigner`。零第三方依赖。

## 七、调试命令

```bash
export PATH=$HOME/bin/platform-tools:$PATH
D=192.168.1.151:5555

# 看播放链路
adb -s $D shell "logcat -d" > /tmp/dy.txt 2>&1
grep -E "Douyin" /tmp/dy.txt | tail -20

# 关键日志含义
#   resolve OK BV1xx q=64 size=5519KB   → 拿到 720P 直链
#   代理开始 206 5651909B ct=video/mp4  → 本地代理开始喂流
#   代理送完 10645KB                     → 一条播完
#   playurl code=-404                    → 该视频无权限，已自动跳过

# 看内存
adb -s $D shell "dumpsys meminfo com.lm.douyin" > /tmp/m.txt 2>&1
grep TOTAL /tmp/m.txt | head -1

# ⚠️ 不要把 adb shell 输出直接接管道（SIGPIPE 会触发看门狗重启）
```
