# T70L 能不能走手机那套 VoLTE？

> 时间：2026-11-04 20:20
> 问题：既然是安卓、有基带，能不能照手机的路子打 VoLTE 语音电话？

---

## 一、一句话答案

**原理同源，但缺的是整套软件栈，不是一个开关。**

手机打 VoLTE 靠四件套，这台机器**四项全缺**（详见下表实测）。它从设计上就不是"手机 + 一个被关掉的开关"，
而是**一台 VoIP 会议终端 + 一个 4G 数据模块**。它的"打电话"本质是 SIP 客户端，从来不是蜂窝语音。

---

## 二、四件套逐项实测

### ① 基带要支持 VoLTE（内置 IMS 协议栈）

```
AT+GTSET="VOLTESW"
→ +CME ERROR: 53
```

`ERROR: 53` = 参数不支持 / 网络拒绝。Fibocom 的 VoLTE 开关命令在 L710 上**不存在**。

```
AT+CGDCONT=5,"IP","IMS"     → OK      ← 只是语法上接受"定义一个叫 IMS 的 APN"
AT+CGDCONT?                 → 只有 cid=1 "CTNET"
```

AT 命令能接受 IMS APN 的**写法**，不代表基带里有 IMS 客户端。区别就像"记事本里能写下'我要减肥'"。

**判定：❌ 基带无 VoLTE 能力。**

### ② 要能注册到运营商 IMS 核心网

```
AT+COPS?    → +COPS: 0,0,"CHN-CT",7    ← act=7，只驻留 E-UTRAN（LTE 数据）
AT+CREG?    → +CREG: 2,4               ← CS 域 unknown，从未注册
AT+CEREG?   → +CEREG: 2,1              ← LTE 分组域正常
```

VoLTE 的前提是：先建 IMS 专用 APN → 跑 IPsec → SIP REGISTER 到运营商 IMS 核心网 → 拿到 200 OK。
这台机器连第一步的 APN 都没配，更没有 SIP REGISTER 的能力。

**判定：❌ 从未建立过 IMS 会话。**

### ③ 基带 ↔ 应用处理器 必须有音频通路

这一项是**数据模块与语音模块的根本分水岭**，也是最多人忽略的一关。

先看 USB 接口描述符（8 个接口）：

```
1-1:1.0 → 02   (CDC Communications，AT 命令口)
1-1:1.1 → 0a   (CDC Data，数据通道)
1-1:1.2 ~ 1.7 → ff ×6  (Vendor specific：DIAG / NMEA / ADB / MODEM 等)
```

**没有任何一个接口是 `01`（USB Audio Class）。**

对比一下：能打电话的 4G 模块（如移远 EC20 语音版、SimCom A76xx 语音版）会多出一组 **UAC 接口**，
系统里直接识别成一张 USB 声卡。这台没有。

再看 SoC 这一侧：

```
/proc/asound/cards → 0 [snddaudio] : snddaudio
/proc/asound/pcm   → 00-01: Voice ac100-aif2-1 : playback 1 : capture 1
```

确实有个叫 `Voice` 的 PCM 通道（全志 AC100 codec 的 AIF2）。**但：**

```
pcm1p/sub0/status → closed
tinymix 中 AIF2 相关路由 → 全部 Off
tinymix 中搜索 modem / baseband / phone → 零命中
```

AIF2 上还挂着 `aif2-bt-net`，说明这条通道在**蓝牙 SCO（免提通话）**用途上，不是基带。

**判定：❌ 没有通往基带的音频通路。就算信令通了，也是"接通了没声音"。**

### ④ Android 框架要有 telephony + IMS 栈

```
/system/framework/ → telephony-common.jar
                     （没有 ims.jar，没有 ims-common.jar）
/system/app/       → TelephonyProvider.apk
                     （没有 Phone.apk，没有 Dialer.apk）
```

这一条最要命：**Android 原生 IMS 栈（`ImsService` / `ImsPhone` / `ImsPhoneCallTracker`）
是 Android 5.1 才引入的。** 4.4 时代想打 VoLTE，只能靠芯片厂自己塞一套私有实现
（高通 QMI-IMS、MTK 的 IMS framework）。全志这个方案**一套都没做**。

框架侧还有个硬开关（上一轮已确认）：

```
framework-res: config_voice_capable = false
```

`false` 的后果是 `PhoneFactory` 根本不会创建 Phone 对象，`TelephonyManager` 对外宣称"本设备不支持语音"。
即使你把 RIL 改通了，框架层也没有任何人会去调它。

**判定：❌ 框架层没有 IMS，也没有语音能力注册。**

## 三、决定性证据：RIL 库对比

RIL（Radio Interface Layer）是框架和基带之间的翻译官。手机能打电话，是因为 RIL 实现了语音相关请求。
把这台机器实际加载的 RIL 和谷歌参考实现放一起对比：

| 能力 | `libsoftwinner-ril-4.4.so`（**实际在用**） | `libreference-ril.so`（谷歌参考实现） |
|---|---|---|
| 拨号 | `requestDial` / `RIL_Dial` | `requestDial` |
| 呼叫列表查询 `AT+CLCC` | **❌ 无** | ✅ 有 |
| 来电响铃 `+CRING:` | **❌ 无** | ✅ 有 |
| DTMF `AT+SATD` | **❌ 无** | ✅ 有 |
| ATD 的用途 | `ATDT*99#` `ATDT#777` `ATDT*98*1#`<br>配套字符串：`PPPD dial port is %s`、`NO DIALTONE` | `ATD%s%s;`（语音呼叫） |

看明白了吗 —— **这台机器 RIL 里的 "dial"，拨的是 PPP 上网号，不是电话。**

`ATDT*99#` / `ATDT#777` 是 3G/4G 拨号上网的标准指令（`*99#` 是 3GPP 通用上网号）。它在"拨号上网"，不是"拨电话"。

**这是本次最硬的一条：RIL 层从未实现过语音呼叫。**

## 四、那"改个开关"为什么不行

常见的三种误解，逐一拆掉：

| 想法 | 为什么不行 |
|---|---|
| "把 `config_voice_capable` 改成 true 就行了" | 改完框架会尝试创建 Phone，但 RIL 没有 `RIL_REQUEST_DIAL` 的语音实现（只有 PPP），会直接返回 `REQUEST_NOT_SUPPORTED`；而且没有拨号 App 去调它 |
| "换个支持 VoLTE 的模块就行" | 换了模块，RIL 还是全志那套、框架还是没有 IMS 栈、AIF2 还是没接基带 —— 三层不动，只换硬件没用 |
| "刷个手机 ROM 就行" | 这 SoC（全志）根本没有手机 ROM。Android 的 telephony 栈依赖厂商闭源 RIL + 基带固件，不是通用件 |

**要真走通，得同时做四件事：**
1. 换一块**语音版**模块（带 UAC 或 PCM 引出）
2. 换 Android 5.1+ 或有厂商 IMS 栈的系统
3. 重写 RIL 的语音实现（AT+CLCC / +CRING / AT+SATD / 音频通路切换）
4. 硬件上把模块 PCM 接到 SoC 的 AIF2

第 4 项是硬件改造 —— 按你的铁律，这条本来就不走。而且做完前面三项，这机器已经等于重造了。

## 五、但有个好消息：它天生就该走 VoIP

抛开"手机"这个框架看，这台机器的配置其实**特别适合打网络电话**：

| 它有的 | 对 VoIP 的价值 |
|---|---|
| 专业会议级扬声器 + 麦克风阵列 | 比手机通话音质好得多 |
| 硬件回声消除（AEC） | 免提不啸叫，这是手机做不到的 |
| OPUS / 48000 编解码（日志里实测） | 宽带语音，比蜂窝 AMR 好一个档次 |
| 稳定的 4G + WiFi 双链路 | 断一条还有另一条 |
| 完整 SIP 栈（`CallSdkImpl`） | 现成的，不用自己写 |

它打不了蜂窝电话，**是因为它本来就不是干这个的**。但它打 VoIP，比大多数手机都强。

所以"打电话"这件事，对它来说正确姿势是：
- **路 A**：给云账号开 PSTN 额度 → 原生拨号盘直接打手机号（最省事，按分钟付费）
- **路 B**：装 SIP 客户端 + SIP 账号 → 打 SIP 号免费，打 PSTN 买中继
- **路 D**：接管云端指向自建 Asterisk → 原生体验 + 完全自主

三条都是 **VoIP 路线**，没有一条需要动 telephony 栈。这才是这台设备的"天赋路线"。

## 附：本次实测命令

```bash
ADB=$HOME/re-tools/platform-tools/adb
D=192.168.1.153:5555
AT() { $ADB -s $D shell "busybox-smp printf '$1\r' | busybox-smp microcom -t 1200 /dev/ttyUSB0"; }

# ① 基带 VoLTE 能力
AT 'AT+GTSET="VOLTESW"'                 # → +CME ERROR: 53

# ② 网络注册状态
AT 'AT+COPS?'                            # → CHN-CT,7 (仅LTE)
AT 'AT+CREG?'                            # → 2,4 (CS域未注册)

# ③ USB 接口类别（找 01 = Audio）
$ADB -s $D shell "ls /sys/bus/usb/devices/1-1/"          # 8个接口
$ADB -s $D shell "cat /sys/bus/usb/devices/1-1:1.*/bInterfaceClass"

# ③ 音频路由
$ADB -s $D shell "cat /proc/asound/pcm"
$ADB -s $D shell "tinymix" | grep -iE 'aif2|modem|voice'

# ④ 框架
$ADB -s $D shell "ls /system/framework/ | grep -i ims"   # 空
$ADB -s $D shell "ls /system/app/ | grep -iE 'phone|dialer'"  # 空

# 决定性：RIL 对比
strings libsoftwinner-ril-4.4.so | grep -iE 'ATD|CLCC|CRING|SATD'
strings libreference-ril.so      | grep -iE 'ATD|CLCC|CRING|SATD'
```

> 注：测试期间曾写入 `AT+CGDCONT=5,"IP","IMS"`，已用 `AT+CGDCONT=5` 清除，
> 恢复后确认仅剩 `cid=1 "CTNET"`，模块状态与测试前一致。
