## 二、服务器端真实情况（2026-11-04 实测）

用设备真身参数查询（`sn=7Y1912128BD03B29`，`ro.sys.generation=1` → 平台是 **crushos**）：

### 系统固件（platform=crushos）
```json

 "appUrl":"https://cdn.xylink.com/as/150130/new/octopus_crush_release-ota-2.24.0-573.zip",
 "versionName":"2.24.0-573","versionCode":22400,"devRevision":573,

```
**`versionCode 22400 / devRevision 573` = 本机当前版本，完全一致。服务器上没有更新的固件。**

### 组件（platform=marlinhw）
```json

 "appUrl":".../WidgetTime_release_1.0.0-5.apk"}
{"packageName":"com.xylink.weatherwidget","versionCode":10000,"devRevision":11,
 "appUrl":".../WidgetWeather_release_1.0.0-11.apk"}
```

### 三条错误平台查询的对照（重要，别用错）
| 查询 platform | 返回 | 说明 |
|---|---|---|
| `nemoos` | blaze_tablet 4.2.2 / 21901-1226（2018-05-14） | ❌ TI OMAP 平台，**和本机硬件完全不同** |
| `nemoawos` | octopus_f1 2.9.0-846（2016-11-11） | ❌ 老版本，且不是本机代数 |
| **`crushos`** | **octopus_crush 2.24.0-573 = 本机版本** | ✅ 正确 |

> ⚠️ 那个 `blaze_tablet-ota-eng_release-1226.zip`（103MB）是给 **TI OMAP blaze_tablet、Android 4.2.2** 的固件包，
> 内含 `boot.img`、`recovery/`、整套 `system/`、`META-INF/updater-script`。
> 其 updater-script 第一行 `assert(getprop("ro.product.device") == "blaze_tablet")`，然后用
> `format("ext4","EMMC","/dev/block/platform/omap/omap_hsmmc.1/by-name/system","0","/system")` **格式化 /system**。
> 本机是 `octopus-f1` / 全志 sun8i（`/dev/block/platform/sunxi-mmc.2/`），平台完全对不上。
> **刷错包 = 变砖风险。** 幸好 assert 会挡住。

## 三、为什么老是提示——根因

`vulture/utils/VersionUtils.java`：

```java
public static int getAppDevVersion(String pkgName) {
    PackageInfo info = ctx.get().getPackageManager().getPackageInfo(pkgName, 16384);
    String[] version = info.versionName.split("-");
    if (version.length != 2) return 0;          // ← 没有 "-" 就返回 0
    return Integer.parseInt(version[1].trim());
}
```

**versionName 必须形如 `x.y.z-N`，否则 devCode 解析成 0。**

重编译时钟时源码 manifest 写的是 `versionName="1.0"`（没有 `-`），于是：
- 时钟 devCode = 0，服务器 5 → `0 < 5` → 判定需要更新
- 天气 devCode = 0，服务器 11 → 判定需要更新

配合 `PackageInfo.less()`：

```java
public boolean less(PackageInfo other) {
    if (this.versionCode >= other.versionCode && (this.versionCode != other.versionCode || this.devCode >= other.devCode))
        return false;
    return true;
}
```

→ 每 120 分钟下载一次、弹一次窗。**纯误报，不是真有新东西。**

## 四、版本号对照表（处置前 vs 处置后）

| 组件 | 处置前 versionCode / versionName | devCode | 服务器 | 处置后 |
|---|---|---|---|---|
| 时钟 | 1 / `1.0` | 0 ❌ | 10000 / 5 | **10000 / `1.0.0-99`** ✅ |
| 天气 | 3 / `3.0` | 0 ❌ | 10000 / 11 | **10000 / `1.0.0-99`** ✅ |

用 `99` 而不是 `5`/`11`：留余量，服务器以后升到 6、20、50 也不会再弹。

## 六、点「立即升级」会发生什么（供参考，已不需要）

**不会丢 root。** 因为走的是普通 APK 安装（`/data/app/`），不动 `/system`。

实际后果只有两条：
1. **时钟秒针消失** —— 被装成原厂 `WidgetTime_release_1.0.0-5.apk`（无秒版）
2. **天气失效** —— 被装成原厂 `WidgetWeather_release_1.0.0-11.apk`（`classes.dex` 仅 10848 字节），
   而本机在 2026-11-01 就自己重写了一套天气（`classes.dex` 49644 字节），原厂版在这台机器上拉不到数据

## 七、如何复现这份核查

```bash
export PATH=$HOME/re-tools/platform-tools:$PATH
SER=192.168.1.153:5555

# 1. 看设备真实平台
adb -s $SER shell 'getprop ro.product.device; getprop ro.sys.generation'
# → octopus-f1 / 1   （两者都满足才是 crushos）

# 2. 查系统固件（正确平台）
curl -s "https://cloud.xylink.com/api/rest/version?platform=crushos&releaseFormat=release&currentVersion=22400-573&sn=7Y1912128BD03B29"

# 3. 查组件
curl -s "https://cloud.xylink.com/api/rest/version?platform=marlinhw&version=1&sn=7Y1912128BD03B29"

# 4. 看当前组件版本
adb -s $SER shell 'dumpsys package com.xylink.timewidget    | grep -E "versionName|versionCode"'
adb -s $SER shell 'dumpsys package com.xylink.weatherwidget | grep -E "versionName|versionCode"'

# 5. 看更新服务判定过程
adb -s $SER shell 'am startservice -n vulture.update_service/vulture.service.UpdateService'
adb -s $SER shell 'logcat -d | grep NEMOUS | grep -E "ignore|shouldDownload"'
```
