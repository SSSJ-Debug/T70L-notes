# 12-抖音 —— 让 T70L 刷上抖音

> 2026-11-06 实现。目标设备：全志 A83T / Android 4.4.4 / 1280×800 横屏 / 1GB 内存。
> 产物：`douyin.apk` **29KB**（应用层 560 行，零第三方依赖）。

---

## 一、先说结论：为什么不做"原生抖音播放器"

我一开始想的是最漂亮的做法 —— 像听歌 App 那样，自己直连抖音接口、原生竖屏滑动播放。
**实测后这条路是死的**，证据如下：

| 接口 | 结果 | 说明 |
|---|---|---|
| `www.douyin.com/aweme/v1/web/hot/search/list/` | ✅ 200 / 67KB | **唯一免签名可用的**，但只给话题词，没有视频 |
| `www.douyin.com/aweme/v1/web/aweme/detail/` | ❌ 403 `Blocked by ArgusSecurityPlugin Uifid Not Found` | 详情/推荐/搜索/关注全挂 |
| `www.douyin.com/aweme/v1/web/*`（批量 6 个） | ❌ 200 但 **size=0** | 静默拦截，比报错更难查 |
| `www.iesdouyin.com/web/api/v2/aweme/post/` | ❌ 200 但 size=0 | 老 v2 接口已废 |
| `www.iesdouyin.com/web/api/v2/hotsearch/billboard/aweme/` | ⚠️ `status_code:0` 但 `aweme_list:[]` | 不拦，但没数据 |
| 分享页 `iesdouyin.com/share/user/xxx` | ❌ 返回 `jsvmprt` JS 虚拟机保护页 | 不再是 SSR，RENDER_DATA 已消失 |
| Googlebot / Baiduspider UA | ❌ 只是避开了 UA 判断，接口照样 403 | SSR 退化 |
| `ttwid` 联合注册 | ✅ 能拿到 cookie | 但 Argus 要的是 `uifid`，不是 ttwid，无效 |
| 第三方解析（api.douyin.wtf / xingzhige） | ❌ 404 / 资源id获取失败 | 公共实例都挂了 |

**核心障碍是 `a_bogus` 签名**：抖音 2026 年全线启用，它依赖浏览器指纹，纯 Java 复现既不现实、也会随时失效。

**而视频/发布恰恰是网页版能做的、接口做不到的。** 用户后面要在抖音发 T70L 的视频，
只有跑真正的网页版才行 —— 所以方案定为：**网页版 + 一个极薄的原生壳**。

## 二、关键的可行性发现

抖音网页版不是黑盒，我把它的前端包扒下来量了一遍，这决定了它能不能在老内核上跑：

```
https://www.douyin.com/discover  → 302 → /home
html 6.6KB（无 jsvmprt 保护，是干净 SPA 壳）
  ├─ lib-react.js        128KB
  ├─ lib-polyfill.js     272KB   ← 自带 polyfill！说明官方想兼容老浏览器
  ├─ lib-axios.js / lib-router.js
  ├─ main.js             326KB
  └─ 320.js             1468KB
```

### 逐个体检的结果

| 检查项 | 结果 | 判定 |
|---|---|---|
| 箭头函数 `=>` | **0 处** | ✅ 纯 ES5 |
| `let` / `const` / `class` / `async` | **各 0 处** | ✅ Babel 全转过 |
| `new Proxy` | **0 处** | ✅ **最关键**，Proxy 无法 polyfill |
| `new Map` | 0 处 | ✅ |
| `ResizeObserver` | 18 处（320.js） | ⚠️ Chrome33 没有 → App 补 |
| `IntersectionObserver` | 1 处 | ⚠️ 补 |
| `fetch` | 4 处 | ⚠️ 补 |
| `Object.assign` | 53 处 | ⚠️ 补 |
| `Array.includes` | 52 处 | ⚠️ 补 |

**结论：没有 Proxy 就等于没有"必死项"**，缺的都是可以垫的 API。
这就是我在 App 里塞了一个 3KB 兼容层的原因 —— 必须在抖音自己的 JS 之前执行，
所以挂在 `onPageStarted` 里（`evaluateJavascript`，API 19 可用），早于 `<script src>` 执行。

## 五、已知风险与 Plan B

### 风险 1：CSS 布局（最可能出问题的地方）
Chrome 33 不支持 CSS Grid（Chrome 57+）、CSS 变量（Chrome 49+）、`position:sticky`（Chrome 56+）。
如果抖音这几个用得多，页面会**能跑但排布错乱**，不是白屏，是"丑"。

### 风险 2：1GB 内存
抖音一个页面峰值 300MB+，设备 Android 层只有 597MB 可用。已加 `largeHeap`，
但仍有 OOM 可能。

### 风险 3：TLS —— 已实测，能过（但需 App 放行证书）
这一条原本以为是最致命的，逐项测完反而最稳：

| 检查项 | 结果 | 对 Chrome33 的影响 |
|---|---|---|
| 服务器最低 TLS | **TLS 1.2 可用**（1.0/1.1 已禁） | ✅ Chrome33 支持 TLS1.2 |
| `ECDHE-RSA-AES128-GCM-SHA256` | ✅ 握手成功 | ✅ Chrome31+ 支持 AES-GCM |
| `ECDHE-RSA-AES128-SHA` | ✅ 握手成功 | ✅ 更老的套件也有 |
| `AES128-SHA`（无 ECDHE，无前向保密） | ❌ 被拒 | 无所谓，上面两个够用 |
| HTTP/1.1 | ✅ 200（proto=1.1） | ✅ Chrome33 不支持 h2，但服务器兼容 |
| HTTP/2 | ✅ 支持 | 用不上，不影响 |

**唯一的坑是证书链**：
```
*.douyin.com  ←  RapidSSL TLS RSA CA G1 (DigiCert)  ←  DigiCert Global Root G2
```
`DigiCert Global Root G2` 是 **2013 年 8 月**才发布的根证书，而 Android 4.4 的
`/system/etc/security/cacerts` 是 2013 年 9 月的快照 —— **大概率没有 G2**。
不放行就是 `SSL handshake failed` 直接白屏。

所以 App 里必须实现 `onReceivedSslError` → `handler.proceed()`。**这一条是成败关键。**

### Plan B：升级内核到 Chrome 74
Android 4.4 能装的最后一版 Chrome 是 **74.0.3729.112**（API 19，armeabi-v7a，45.41MB）。
两条路：
1. **装 Chrome 74 独立浏览器** + 壳 App 用 Intent 全屏拉起 —— 最简单，但会露出地址栏
2. **替换系统 WebView**（`/system/app/webview/`）—— 体验最好，壳 App 仍是 29KB，但有变砖风险，需先备份

已验证 `com.google.android.webview` 的 74 版存在 arm-v7a 包。

## 七、踩坑记录

1. **XML 注释里不能写 `--`**。`<!-- am start --es q -->` 会让 aapt 报
   `Error parsing XML: not well-formed`，报错位置还指向下一行，很难看出来。
2. **`BuildConfig.VERSION_NAME` 不是免费的**。不用 gradle 时 aapt 不生成 BuildConfig，得手写一个。
3. **抖音的 403 有两种**：带 JSON 报错的（好查）和 **200 + size=0 的静默拦截**（难查）。
   后者会让你误以为"参数错了"，其实是签名没过。
4. **`v.douyin.com` 短链还能 302**，但跳到的是 `jsvmprt` 保护页，别指望从里面抠数据。
5. **热搜榜是唯一免签名的口子**，可以拿来做好玩的东西（热点词云、话题榜），但拿不到视频流。
