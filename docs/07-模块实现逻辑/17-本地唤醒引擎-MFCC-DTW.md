## 二、为什么不能用合成音"代替"真人训练（重要教训）

我原以为可以用设备扬声器播放合成音代替真人，跑通后交给用户。**这条路走不通**，实测数据：

```
合成音经"扬声器 → 麦克风 → 3:1 抽取"之后：
  能量只剩 260ms 超过门限（完整"小智"应该 400~700ms）
  频谱变成 85% 能量堆在 800Hz 以下、自相关仅 0.05（不是语音，是稳态噪声）

用这种失真片段训练出的模板 = 噪声模板
→ 设备上任何 260ms 的噪声段都能匹配上（top3 距离 0.34~0.41 < 阈值 0.726）
→ 静置 2 分钟误唤醒 9 次
```

**验证方法（可复现）**：把设备实际录到的段 dump 成 wav，在 Mac 上用同一份
`Mfcc.java` / `Dtw.java` 重算 —— 同一份录音，Mac 算出 2.7~2.9（正确），设备上算出
0.4（错误）。差异 100% 来自模板，不是算法。

**结论**：模板必须来自**真人对麦克风说话**。合成的、远场录的、能量不足的片段，训练出来都是废的。

## 三、架构

```
主循环（100ms 一帧，48k 立体声）
   │  Pcm.to16kMono → 1600 样本
   ├─→ Kws.feed()  ← 只做一次数组拷贝 + 入有界队列，绝不阻塞
   │       │
   │       └─→ KWS 线程（MIN_PRIORITY+1）
   │             逐 10ms 帧：MFCC → 能量端点检测 → 段结束 → CMN → DTW
   │             命中 → volatile Hit（含"小智"那一段的原始 PCM）
   │
   └─→ takeHit() → beep() + beginTurn() + 把预录 PCM 当本轮开头送云端
```

### 关键设计

**1. MFCC 参数（`Mfcc.java`）**
- 16 kHz / 25 ms 窗 / 10 ms 步 / 512 点 FFT / 26 Mel（60~7600 Hz）/ 24 倒谱（丢掉 c0）
- 25 ms 是折中：短了抓不到 100 Hz 基频周期，长了相邻音节糊在一起
- 丢掉 c0 + CMN，把"音量/距离/麦克风增益"彻底解耦 —— 这是远场也能唤醒的前提

**2. DTW（`Dtw.java`）**
- Sakoe-Chiba 带 + 路径归一化（除以 n+m）
- ⚠️ **带宽必须能容下两段长度差**：`band = max(|n-m|+6, 0.3*max+4)`
  早期版本只有 `0.3*max+4`，n=30 / m=79 时无解，直接返回无效值 ——
  实测 8 条模板里有 5 条**从来没参与过判定**

**3. 判据：Top-3 平均，不是最小值（`Kws.match`）**
- 10 条模板里只要 1 条"凑巧"像就命中，蒙中概率不低（实测 4.5 次/分钟）
- 真人说同一个词是**十条都像**，噪声只能蒙中一两条
- 取前 3 名平均，把"碰巧"的成本从 1/10 提到 (1/10)³ 量级

**4. 浊音谷（辅助判据）**
- 段内最小的 3 个谱平坦度取平均。真语音一定有浊音帧（0.05~0.2），噪声没有
- ⚠️ 用"平均"是无效的：段里混着静音帧，语音段平均 0.444、噪声段平均 0.41，完全重叠

## 四、四道防自激闸（血泪）

设备**没有 AEC**（`audio_effects.conf` 里 pre_processing 段是注释的），
扬声器的声音全被麦克风录回去。不拦住就是无限自问自答。

| 闸 | 做什么 | 教训 |
|---|---|---|
| `Kws.suppress` | 播报期间丢弃积压帧**并重置段状态** | 只靠"主循环不喂"不够：队列里那十几帧会在播报结束后才被分析，而 TTS 与模板同源（距离 0.23），必然命中 |
| 时间戳 | 帧超过 1 秒未处理就丢 | vulture 每秒 180 次录音重试抢 CPU，KWS 处理滞后过 1.8 秒 |
| `endTurn` 不清 `playing` | `if (mp == null) playing = false` | 原来无条件清，"在呢"播放中被判成"没在播"，立刻录到提示音又开一轮 |
| `onStt` 入口关闸 | 识别文本一到就设 `quietUntil += 400ms` | 云端先推文本、30~200ms 后才推 TTS；这 30ms 里主循环还在待命态，直接抓到 25000 的能量 |

## 五、怎么用（给用户）

1. 打开「小智」设置页 → 左栏底部「**学我的声音**」
2. 站在**离设备 1~2 米**、环境安静的地方
3. 对着它说 12 遍「小智」，**每遍说完停一下**（等数字 +1）
4. 看到 **✓ 学好了** 就行，日志会打印 `模板 N 条 ｜ 类内 X ｜ 阈值 Y`

**参数含义**
- 类内距离：你自己 12 遍之间的平均差异，越小越稳（0.2~0.5 正常）
- 阈值 = 类内 × 1.6，夹在 [0.38, 0.90]
- 类内 > 0.72 会直接判"样本差异太大"，要求重录（环境太吵/距离不一致）

**没训练时**：自动降级到原来的云端唤醒，行为和以前一样，不会更差。

## 六、参数速查

| 常量 | 值 | 含义 |
|---|---|---|
| `MIN_FRM` | 32 | 段长下限 320ms，低于此不做匹配（模板必须够长） |
| `MAX_FRM` | 160 | 段长上限 1.6s，超出强切 |
| `END_SIL` | 18 | 连续 180ms 静音判段结束 |
| `SLIDE_STEP` / `SLIDE_MAX` | 3 / 12 | 长句里滑窗找唤醒词，最多滑 360ms |
| `COOL_MS` | 900 | 命中后冷却，躲自己的提示音 |
| `gate` | `max(nEst*1.35, 200)` | 切段门限。压得低是因为判定靠音色不靠能量 |
| 阈值 | `intra*1.6` ∈ [0.38, 0.90] | 见上 |

## 七、排障

**日志里看不到 `/data/.../xz.log`**：权限 600，要 `adb shell "su 0 cat ..."`

**想抓段音频分析**：
```bash
adb shell "su 0 mkdir -p /data/data/com.lm.xiaozhi/files/kwsdump"
adb shell "su 0 chown u0_a52:u0_a52 /data/data/com.lm.xiaozhi/files/kwsdump"
# 之后每段都会存成 wav，最多 60 个
```
⚠️ 用完记得 `rm -rf`，否则一直写盘。

**误唤醒太多**：先看日志的 `top3=` 值。如果真人说话也在 0.5 以上，说明模板质量差，
重录（更安静、距离固定、语速一致）。

**完全唤不醒**：看日志有没有 `Kws: 段`。
- 没有段 → 门限太高或麦克风没数据
- 有段但 top3 都在 1.5 以上 → 模板和你现在的声音不像，重录

## 八、文件

| 文件 | 行数 | 职责 |
|---|---|---|
| `Mfcc.java` | ~180 | 特征提取（含 flatness） |
| `Dtw.java` | ~80 | 带约束的 DTW |
| `Kws.java` | ~560 | 端点检测、匹配、模板读写、线程 |
| `KwsActivity.java` | ~230 | 训练界面（只读状态，不开第二路录音） |

⚠️ **训练不能自己开 AudioRecord**：这台 HAL 一旦 stop 再 open，输入轨道常常拿不回来
（read 永久返回 0），只能重启进程。所以训练复用服务那条长命录音流。
