## 二、唤醒不灵的四层原因（按影响排序）

### 1. VAD 绝对门槛定太高（最主要）
```
旧：sens=1 → {900, 24}   → 底噪 195 时阈值 = max(900, 468) = 900
新：sens=1 → {120, 15}   → 底噪 384 时阈值 = max(120, 576) = 576
```
旧值照着"近处正常音量"定的，几米外人声 rms 只有 400~800，**永远够不到 900 的门槛**，所以"在旁边喊怎么都没反应"。

### 2. 底噪估计永远学不会环境（最隐蔽）
原代码两处把它卡死：
```java
// ① 每轮结束时 resetNoise = true
if (resetNoise) noiseEst = min(max(20, rms), 100);   // 死写上限 100
// ② 上升速率只有 0.008/帧
else noiseEst = noiseEst*0.992 + rms*0.008;          // 107→400 要 16 秒
```
房间稳态噪声 400，估计值永远 100~135 → 阈值 200 → **噪声本身就把开口触发了**，然后每句录满 3.2 秒。

修：
```java
if (resetNoise) { noiseEst = max(20, min(rms, 600)); }   // 跟随当前帧，封顶 600
else noiseEst = noiseEst*0.955 + rms*0.045;              // 2~3 秒跟上
```
实测修复后：`[空闲] rms=378 底噪=363 阈值=544` —— 噪声 378 不误触发，说话 800+ 能进。

## 三、连续对话（设置页那个开关）为什么"开了不接、关了还聊"

### 开了不接：近场过滤用削波峰值当基准
```java
// 旧
long near = max(2500, sessionPeak * 0.35);   // sessionPeak = peakAbs，常削波到 32768
                                             // → near = 11468，正常说话 peak 5000~9000 全被丢
// 新
if (sessionPeak > 0 && sessionPeak < 20000) {
    long near = max(1000, sessionPeak * 0.12);
}
```

### 掉了就不回来
```java
// 旧：云端只要有一轮没答，整个会话立刻掉线
boolean stay = keepSession || (accepted && p.continuous);
// 新
boolean stay = keepSession || (p.continuous && (accepted || inSession));
```

### 关了还聊：设置页改了要等下一轮才生效
界面只写 SharedPreferences，服务在 `beginTurn()` 才重读 → 点完"关闭"当前这轮还在会话里，最长拖到静默超时 25 秒。
修：加一次性信箱 `Prefs.sContPending`，主循环每帧取，取到就立刻 `endSession()`。

### 新增：用嘴开关
- 「小智，开启连续对话」/「关闭连续对话」/「连续对话」（单独说=切换）
- 「退出对话」「不聊了」「先这样」「拜拜」→ 立即结束会话
- 开/关都回一声"在呢"当确认音

## 六、畅聊模式（chatMode，2026-11-07 19:40 新增）

### 6.1 为什么要它，和"连续对话"什么关系

| | 连续对话（`p.continuous`） | 畅聊模式（`chatMode`） |
|---|---|---|
| 存哪 | SharedPreferences，**持久** | 只在内存，进程死了就没了 |
| 有效期 | 一直是开着的 | **只这一次会话** |
| 怎么进 | 设置页点 / 喊「开启连续对话」 | 喊一句暗语 |
| 退出去哪 | 还得再喊一次关闭 | 说完「不聊了」立刻回落 |
| 风险 | 全局开着 → 客厅随便说句话它都可能接 | 只在这几分钟里免唤醒 |

用户原话是"心血来潮想聊三五分钟，只要我不说结束它就不结束"。
这要的不是全局开关，是**一次性会话**。所以两者并存：日常仍用 continuous=false（每条喊名字），
心血来潮时用暗语开一场，聊完自动落地。

### 6.2 状态机

```
待命（每条都喊「小智」）
   │  暗语：「小智，陪我聊聊」
   ▼
畅聊（张嘴就说，不用喊名字）
   │  退出词：「不聊了 / 拜拜 / 聊够了」
   │  或静默 300 秒
   ▼
待命
```

### 6.3 进入暗语

- **主推：「小智，陪我聊聊」** —— 实测 100% 命中，四个字全是常用字
- 同义：我们聊聊天 / 说说话 / 畅聊 / 长聊 / 唠嗑 / 聊会儿 / 聊一会
- 容错规则（`chatIntent`）：**人称 + 聊音** 同时命中就算
  ```
  who  = 陪我 | 咱俩 | 我们 | 和我 | 跟我
  talk = 聊 | 疗 | 辽 | 唠
  ```
  加"疗/辽"是因为 19:39 实测 ASR 把「小智聊会儿」听成了「**小治疗慧儿**」，
  字面匹配直接失效。但"疗"必须和人称同时出现，日常说"治疗""辽宁"不会被误判。

### 6.4 退出词

`不聊了 / 别聊了 / 不聊啦 / 聊够了 / 先这样 / 拜拜 / 再见 / 就到这 / 结束了 / 结束吧`

命中后：结束会话 → 播"在呢" → 回待命（下次开口又要喊名字）。

### 6.8 指令执行与畅聊的硬隔离（2026-11-07 20:00 追加）

#### 为什么要补这一刀

用户原话："平时我只喊小智开灯、小智关灯，这时候它不会进畅聊对吧？我开完灯关完灯
跟家里人聊天，它也往上接话，就逻辑冲突了。"

这不是多虑，**实测当天就复现了**。19:48 用户在旁边口述需求，说出了
"…比如说小智陪我聊聊天，它才会进入长聊天…"，设备在同一个房间把这句听进去，
**直接进了畅聊模式**，之后家人所有正常说话全被当成对话接走。


#### 设计原则：两种指令，两种生命周期



#### 实现一：`dropToIdle()` —— 指令执行命中即落地






#### 实现二：`wakeAtHead()` —— 暗语必须「小智」在句首


判据从 `isWake(t)`（contains）换成 `wakeAtHead(t)`，于是：

| 句子 | 旧逻辑 | 新逻辑 |
|---|---|---|
| 小智，陪我聊聊 | ✅ | ✅ |
| 嗯小智陪我聊聊 | ✅ | ✅（容忍 2 字前缀） |
| 你下次说小智陪我聊聊天试试 | ✅ 误进 | ❌ |
| 比如说小智陪我聊聊天它就会进畅聊 | ✅ 误进 | ❌ |

另外删掉了 `inSession` 这条通道 —— 它会让人在会话里随口一句带"聊"字的话重新激活畅聊，
等于自己给自己续命。

#### 实现三：chatMode 三级防残留

| 级别 | 位置 | 作用 |
|---|---|---|
| ① 超时 | 主循环 `idleTo = chatMode ? 300 : 25` | 静默 5 分钟自动退 |
| ② 自检 | `beginTurn()` 每轮开头 | `chatMode` 挂着但会话已不在 → 清理 |
| ③ 硬上限 | `beginTurn()` 同上 | 畅聊超过 **15 分钟** → 强制落地 |

②③ 是新增的。为什么要 ③：用户忘了说「不聊了」、或者误触发后没人管，
畅聊会一直挂着免唤醒，那是最隐蔽的一种"变成永久全局开关"。
