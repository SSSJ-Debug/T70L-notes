# T70L 环形灯常亮 / 电话图标消失 / 小智听不见 —— 同源根因

> 2026-11-07 13:20 定案。三个看似无关的问题，**根子是同一个 App**。

## 一句话结论

**`vulture.app.home`（小鱼易连会议 App，系统签名）不能禁用、不能反复 force-stop。**
它同时承担三件事，少一样就出一样故障：

| 职能 | 消失后的症状 |
|---|---|
| `vulture.appwidget.TelephoneAppwidget` —— 桌面「电话」图标的 provider | 电话图标消失 / 变成空白 |
| `vulture.service.PeripheralService` —— 呼吸灯状态机（`BreathLightController`） | **电源键环形灯常亮，只能恢复出厂** |
| `vulture.receiver.SysBootupReceiver` —— `com.nemo.action.GOHOME` 广播的原厂发送者 | 在软件里按电源键直接息屏，回不到桌面 |

## 灯为什么是"常亮"而不是"不亮"

厂商 `PowerManagerService` 的自定义逻辑（解析自 `services.jar`）：

```java
private boolean isHome = true;                 // 默认 true
private void goToSleepFromNative(long t, int r) {
    if (!isHome) { 发 com.nemo.action.GOHOME 广播; isHome = true; }
    else goToSleepInternal(t, r);              // 真正息屏
}
```

呼吸灯由 `PeripheralService` 里的 `BreathLight` 状态机（`BaseState` / `InCallState` /
`BlankModeState` / `NoInternetState`）驱动，通过 AIDL `driverservice.breath_light`
→ `ControllerManager.setBreathLight(int,int,int)` → native 写 GPIO。

**App 被停 → 状态机没了 → 灯停在最后一次点亮的电平上**。
而正常开机是 uboot 点亮、进系统后由这个服务熄灭，所以表现就是"开机亮一下然后一直亮"。

## 排查中被排除的错误方向

| 怀疑对象 | 实测结论 |
|---|---|
| `gpio145` (PE17) | **不是灯**。拉低到 0 后灯仍亮；重启后自动回到 1。它另有用途 |
| `gpio125` (PD29) | 归 `vulture.driver_service` 管，out lo。不是环形灯 |
| 我们的守护脚本 | 已 `grep -n gpio /data/local/tmp/*.sh`，**一处都没有** |
| `/sys/class/leds` | 本机**不存在**这个目录，LED 全是裸 GPIO，无 LED class 驱动 |

`vulture.driver_service` 的 `libdriver_nemo.so` 里硬编码的 GPIO 是：
`0 / 34 / 42 / 101 / 125 / 161 / 162 / 163 / 202 / 203 / 204 / 232 / 234 / 354 / 356 / 361`
—— 里面**没有 145**。

## 小智的麦克风：这台设备的增益窗口极窄

Android 4.4 全局只允许一个录音客户端，先到先得。`vulture.app.home` 开机先起，
一启动就开 `AudioCapture`，麦被占死，小智 `AudioRecord.start()` 直接 `status -38`。

**不能靠停 App 解决**（会把灯和电话一起搞挂），正确顺序是：

```
① am force-stop vulture.app.home      # 让它交出麦克风
② 等小智真的开始读数据（看 AudioRecord 无报错，不是"进程在"就行）
③ am startservice vulture.app.home/vulture.service.PeripheralService
   → 进程活了，widget 和呼吸灯恢复；此时它抢不到麦，只有会议录音功能受影响
```

脚本：`/data/local/tmp/mic_owner.sh`（`check` 参数只看状态）。

### 增益实测三档（`tinymix` 序号）

| ADC volume(9) | ADC gain(13) | 待命 rms | 说话 rms | 结果 |
|---|---|---|---|---|
| 176 | 3 | 11 | <900 | 喊破喉咙也没反应 |
| 220 | 4 | — | 恒定 25000~30000 | 全帧削波，VAD 判不出句尾 |
| **190** | **3** | 174~480 | 10000~20000 | **最佳档，长句识别准确** |

配套：`tinymix 0 176`、`tinymix 1 176`、`tinymix 14 4`、`tinymix 15 4`。

### 仍然存在的物理限制

这台设备录音时"静音"段 rms 也有 **5000~13000**，与语音 **10000~20000** 严重重叠，
信噪比只有 2:1，纯能量 VAD 断不准句尾。当前用 `MAX_CHUNKS = 32`（1.92 秒）兜底，
延迟约 3 秒。要再快只能上**本地唤醒词识别（KWS）**，不依赖云端。

## `XzService.java` 本轮的参数调整

| 常量 | 旧 | 新 | 理由 |
|---|---|---|---|
| `PREROLL` | 6 | 12 | 开口判定滞后 ~0.5s，360ms 预录会丢句首（实测只识别到"怎么样啊"）。25 帧又太长，发送慢导致 `chunks=0` |
| `MAX_CHUNKS` | 50 | 32 | 断句不可靠时用上限保响应 |
| `SIL_END` | 4 | 3 | 静音线改成本句峰值×0.6（上限底噪×8），3 帧即收尾 |
| `localPeak` | — | 每句重置 | 原来继承上一轮峰值，会把阈值抬死 |
