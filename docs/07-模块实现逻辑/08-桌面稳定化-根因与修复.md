# 桌面反复反弹 + 小智崩溃 —— 根因与修复（2026-11-06 下午）

## 一、现象

1. 桌面时不时"跳回原厂桌面"，装的应用全部消失
2. 小智不停地弹「很抱歉，小智已停止运行」
3. 在应用里按电源键不是回桌面，而是直接息屏

## 二、三个独立的根因（不是一回事）

### 根因 A：vulture 会主动把桌面重置成原厂默认布局

`desk_watchdog.sh` 的注释里早就记着这条，但当时没往这个方向查：

```
网线拔掉 → vulture.network_service 断连 → vulture.app.home 退出
→ vulture.watchdog 触发 nemo.intent.update.RESTART
→ com.xylink.launcher 重置成默认布局（电话/日程/消息中心…）
```

触发条件不止拔网线：**装/卸 APK（PACKAGE_ADDED 广播）、桌面进程被杀、网络事件**都会触发。

实测：桌面被重置后，`item_info` 会先掉到 3~4 条，12~15 秒后才慢慢恢复。
**这段时间里如果守护脚本急着"修复"，就会和桌面的重建过程打架**，越修越乱。

### 根因 B：守护脚本自己也有一半责任（三个致命设计）

`launcher_guard.sh` 原来有三个问题，全都指向"越修越乱"：

| 问题 | 后果 |
|---|---|
| 签名校验用 `sqlite3` 直读数据库 | 实测同一时刻 Provider 看到 12 条、SQL 只看到 8 条（桌面事务未落盘）→ **每轮都误判"4 条目缺失"→ 反复补写** |
| 校验要求"完全等于标准布局" | 系统塞回「日程」「消息中心」→ 签名永远对不上 → 连续 2 轮触发整表恢复 → **kill 桌面** → 桌面重建 → 系统再塞回，死循环 |
| 补条目清单是硬编码的 5 个 | 漏了「录像机」「文件夹」「设置」→ 桌面重启后这 3 个真丢了也补不回来 |

### 根因 C：小智 App 的空指针崩溃

```
FATAL EXCEPTION: xz-loop
java.lang.NullPointerException
    at com.lm.xiaozhi.XzService.loop(XzService.java:283)
```

麦克风看门狗为了救"读到静音"卡死，会调 `stopRec()` 把 `rec` 置 null；
而主循环此时正卡在 `rec.read()` —— 直接空指针 → 工作线程死 → 系统弹「很抱歉，小智已停止运行」→ 守护拉起 → 再崩 → 无限弹窗。

## 三、修复

### 3.1 小智 App（`com.lm.xiaozhi`）

- `loop()` 外面包一层 `try/catch(Throwable)`：任何异常只记日志 + 重开录音 + 2 秒后继续，**绝不让工作线程把进程带走**
- 所有 `rec.read()` 改成先抓局部引用再判空（`AudioRecord r0 = rec; if (r0 == null) break;`）
- 看门狗在 `playing == true`（正在播回答）时跳过判断 —— 播放时录音本来就被停了，不然每句回答中间都要重开一次录音

### 3.2 守护脚本（`launcher_guard.sh` v3）

- **签名改走 ContentProvider**（`content query`），和桌面看同一份数据，不再有读写时序误判
- **校验改成"包含式"**：只要求标准布局里的条目存在且坐标正确，多出来的不管
- **数据库触发器拦截**：
  ```sql
  CREATE TRIGGER trg_block_extra BEFORE INSERT ON item_info
  WHEN NEW.title IN ('日程','消息中心') BEGIN SELECT RAISE(IGNORE); END;
  ```
  从源头插不进来，比"删了又被加回来"稳
- **补条目改成遍历标准布局全量**，以后加新应用自动纳入，不会再漏
- **二次确认**：疑似偏离先等 15 秒再看一次，避开桌面重建的中间态
- **整表恢复彻底停用**：不再 `DELETE FROM item_info`，不再 `kill -9` 桌面。只做逐条修补

### 3.3 开机启动

`boot_init.sh` 里补上 `desk_watchdog.sh start` —— 它是 `launcher_guard` 的保活（每 30 秒确认还活着），之前只在手动启动时才有。

## 五、关于电源键（重要，别再踩）

在应用里按电源键应该"第一次回桌面、第二次锁屏"。这个逻辑依赖系统能解析到 HOME。

**我这次一度 `pm disable-user com.android.launcher`（原厂 Launcher2），想把 HOME 锁死在
com.xylink.launcher —— 结果电源键直接变成息屏，因为 HOME 解析链被切断，系统找不到可返回的桌面。**

已恢复 `pm enable com.android.launcher`，电源键行为正常（实测两次按键：回桌面 → 锁屏）。

> 铁律：**不要禁用 com.android.launcher**。想稳定 HOME 只能靠守护把 com.xylink.launcher 顶回来，
> 不能靠禁用另一个 HOME。

> **2026-11-07 补：这里还有第二个、更常见的根因。**
> 上面这条讲的是「HOME 解析链断了」。但同一个表象（在 App 里按电源键直接息屏）
> 还有另一个原因：`PowerManagerService` 里有个布尔位 `isHome`，**默认 true**，
> 只靠 `com.nemo.action.HOME` 广播更新，而原厂发送者是 `vulture.app.home`。
> 我们的 `mic_guard.sh` / `boot_svc.sh` / `cam_guard.sh` 会 `force-stop` 它抢麦抢摄像头，
> 一杀这条线就断，**电源键立刻退化成纯息屏**。
> 完整解析证据、诊断法和守护方案见 **`13-电源键Home逻辑-根因与守护.md`**。
> 现在由 `homekey_guard.sh` 兜住，不再依赖 vulture 存活。

# 补充（2026-11-06 16:20–17:00）：静态分析 分析 + 数据库层根治

## 八、审计取证：真的有人整表清空

在 `_setting.db` 里加了一个 BEFORE DELETE 审计触发器：

```sql
CREATE TABLE _del_audit (id INTEGER PRIMARY KEY AUTOINCREMENT, ts TEXT, title TEXT, screen INTEGER, cellX INTEGER, cellY INTEGER);
CREATE TRIGGER trg_audit_del BEFORE DELETE ON item_info
BEGIN INSERT INTO _del_audit VALUES (NULL, datetime('now','localtime'), OLD.title, OLD.screen, OLD.cellX, OLD.cellY); END;
```

抓到的事实（16:24:51 那一秒）：


**同一秒删掉全部 14 条 = 不是逐条删，是 `DELETE FROM item_info`（整表清空）。**

随后桌面只从 AppWidgetService 恢复回来 3 个 widget（时间/天气/电话），
其余快捷方式全没了 —— 这就是用户看到的"装的软件全消失"。

精细监控（每 5 秒采样）还原出的循环节奏：

```
14 条 → (60s) → 8 条 → (补 3) → 11 条 → (补 3) → 14 条 → (60s) → 8 条 → …
```

守护补完 → 60 秒后又被清 → 再补。**这就是"桌面反复反弹"的真身。**

### 分析补充

- 桌面 APK 是 `/system/priv-app/MarlinLauncher.apk`，只有 238KB / 177 个类，里面**没有默认布局 XML**
  （`res/` 下只有 layout，没有 default_workspace）——所以那 3 条不是"默认布局"，是 AppWidget 回填。
- `LauncherProvider`（`content://com.xylink.launcher.data/ItemInfo`）的 delete 在 字节码 里确实
  调用了 `SQLiteDatabase.delete(table, where, args)`，**where 传 null 就是整表清空**。
- 解包工具 把 `packed-switch` 的 case 体丢了（解析出来全是 `return 0`），必须以 字节码 为准。
- 触发源没能定位到具体进程（Android 4.4 没有 Provider 调用方审计，logcat 又被 NEMO_UI 刷屏冲掉）。

## 九、根治方案：SQLite 层锁死，不再比手速

既然拦不住谁去 `DELETE`，就让删除**物理上无效**：


-- 2) 同名条目不许重复插入（防止重建时冒出两个同名图标）
CREATE TRIGGER trg_dedup_insert BEFORE INSERT ON item_info
WHEN EXISTS(SELECT 1 FROM item_info WHERE title = NEW.title)
BEGIN SELECT RAISE(IGNORE); END;
```

`RAISE(IGNORE)` 会让**整表 DELETE 只删掉不在清单里的条目**（比如系统的日程/消息中心），
清单里的 11 个连一行都删不掉。系统怎么清都清不动。

⚠ 踩坑记录：**不要用 BEFORE INSERT 去拦「日程」「消息中心」**（`trg_block_extra`）。
加了这个之后桌面每 60 秒把快捷方式清一遍，疑似桌面把"插入被 IGNORE"当成事务失败而回滚重建。
已撤除。包含式校验已经让多余条目无害，不需要拦插入。
