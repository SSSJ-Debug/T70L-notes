# 11 · 听歌 —— 实现逻辑

> 2026-11-06 晚。目标：让 T70L 变成一台"什么歌都能搜到、点开就放"的在线音箱。
> 结论先放这儿：**B 站做主力、网易云做音质补充，酷我砍掉**。理由在 §2。

---

## 1. 一句话架构

```
输入（键盘 / 小智语音 intent）
   ↓
Sources.search()  ← 双线程并行
   ├─ Bili.search()      B 站 wbi 搜索（覆盖全网）
   └─ Sources.neteaseSearch()  聚合 API（正版 320k + 歌词 + 封面）
   ↓ 合并去重 + 按"像不像一首正经歌"打分排序
Song{ title, artist, source, id, coverUrl }
   ↓ 点一首
Sources.resolve() → 直链（https）
   ↓ 4.4 媒体栈吃不下 https
StreamProxy（127.0.0.1:18777）→ 明文 http 喂给 MediaPlayer
   ↓
MediaPlayer → AC100 功放 → 出声
```

文件（7 个类，共约 2100 行）：

| 文件 | 职责 |
|---|---|
| `MainActivity.java` | 全部 UI + 播放控制 + 搜索历史（单 Activity） |
| `Sources.java` | 多源聚合：搜索合并、去重排序、直链解析、歌词 |
| `Bili.java` | B 站：WBI 签名、搜索、纯音频轨、MP4 兜底 |
| `Http.java` | 统一 HTTP：**强制 TLS1.2 + 接受任意证书**（4.4 专用） |
| `StreamProxy.java` | 本地 http 代理，解决 NuPlayer 不认 https |
| `CoverLoader.java` | 封面下载 + 16 张 LRU 缓存 + 圆角绘制 + 占位图 |
| `Lrc.java` / `Song.java` | LRC 解析 + 歌词控件 / 数据模型 |

## 2. 音源选型（这一节是整件事的核心，别再走回头路）

### 2.1 实测结论表

| 音源 | 搜索覆盖 | 直链质量 | 结论 |
|---|---|---|---|
| **B 站** | 全网（周杰伦、五月天、冷门全有） | AAC 132k/184k，MP4 容器 | ✅ **主力** |
| **网易云**（聚合 API） | 缺周杰伦等大版权 | MP3 320k + 封面 + 歌词 | ✅ **补充** |
| 酷我 | 看着全 | **假成功**：正版歌一律返回 181KB 提示音 | ❌ **砍掉** |
| QQ 音乐 | 全 | 需要签名，Meting 公共实例已 404 | ⏸ 备选未通 |

### 2.2 酷我为什么必须砍

`antiserver.kuwo.cn/anti.s?type=convert_url&rid=MUSIC_xxx` 这个老接口看着完全正常：
HTTP 200、`Content-Type: audio/mpeg`、返回一个像模像样的 URL。

但实测：

```
晴天(周杰伦)   rid=MUSIC_228908    → 181,521 字节
晴天v2        rid=MUSIC_80456317  → 181,521 字节   ← 同一个文件
温柔(五月天)   rid=MUSIC_386538    →  81,629 字节
江南(林俊杰)   rid=MUSIC_108914    →  81,629 字节   ← 也是同一个
晴天+告白气球  rid=MUSIC_197123020 → 8,100,863 字节  ← 只有这种"用户上传"能播
```

**不同 rid 返回同一个文件** = 版权曲库被掐，接口给的是提示音。
这种"假成功"比直接报错更坑：用户点了歌、进度条走了、放出来是废话。
所以整个源删掉，连带 `kuwoSearch()` 也只留档不调用。

### 2.3 为什么 B 站能当主力

实测搜「晴天 周杰伦」，前 5 条：

```
【𝐇𝐢-𝐑𝐞𝐬无损音质】｜《晴天》- 周杰伦     4:30   ← 正是原曲长度
【4K修复】周杰伦 - 晴天MV                  5:17
晴天 周杰伦                                4:30
【4K Hi-Res】晴天-周杰伦                   4:30
周杰伦——《晴天》                           4:27
```

取音频轨：`dash.audio` 里有 30216(64k) / 30232(132k) / 30280(184k) 三条，
选 30280，实测 HTTP 200、6.2MB、头部 `ftypisom`（标准 MP4），4.4 能解。

**B 站的代价**是标题脏。`Bili.splitTitle()` 负责洗：

```
「【4K修复】周杰伦 - 晴天」  → 标题=晴天 / 歌手=周杰伦
「周杰伦——《晴天》」        → 标题=晴天 / 歌手=周杰伦
「晴天 周杰伦」              → 标题原样 / 歌手用 UP 主兜底
```

规则：剥掉开头最多 4 层 `【】[]（）()` 前缀和 `| 丨 -—` 分隔符，去掉书名号，
再按 ` - ` / `－` / `—` 切左右。

### 2.4 排序：怎么把"正经歌"排前面

`Song.rankScore(keyword)` 是负向打分（越小越靠前）：

| 命中 | 加罚 |
|---|---|
| 标题 == 关键词 | −40 |
| 标题以关键词开头 | −25 |
| 歌手含关键词 | −10 |
| 含「伴奏 / KTV」 | +60 |
| 含「铃声 / 片段 / 试听」 | +55 |
| 含「合集 / 串烧 / 连播」 | +45 |
| 时长 < 45s | +50 |
| 时长 > 600s | +40 |
| 含「翻唱 / cover」 | +35 |
| 含「钢琴 / 吉他 / 纯音乐」 | +30 |
| 320kbps | −6 |

去重 key = `抹掉括号内容+符号的标题 | 第一个歌手`，所以「晴天(女声版)」和「晴天」不会互相吃掉。

## 3. 四个必须踩过去的坑

### 3.1 Android 4.4 的 TLS：不处理就一条接口都连不上

两个独立问题：

1. **协议**：4.4 的 `HttpsURLConnection` 默认只肯谈 TLSv1。现在的音乐接口基本要求 TLS1.2+，
   不强制协商就会 handshake 失败（表现为 `SSLException: Connection closed by peer`）。
2. **根证书**：4.4 的证书库停在 2014 年。Let's Encrypt 的 ISRG Root X1 是 2016 年才有的，
   `music-api.gdstudio.xyz` 这类站点直接证书链校验失败。

`Http.factory()` 的做法：`X509TrustManager` 全放行 + `SSLSocketFactory` 包一层，
在 `createSocket` 里把 `enabledProtocols` 按 `TLSv1.2 → 1.1 → 1.0` 的顺序挑**系统真支持的**塞进去。

> 安全性：本机只请求固定几个公开音乐接口，不传账号密码，接受任意证书的代价可以忽略。

### 3.2 NuPlayer 不认 https → 本地代理

4.4 的媒体栈 `setDataSource(https://...)` 直接报 `1/-1004`。
`StreamProxy` 在 `127.0.0.1:18777` 起一个迷你 HTTP 服务：Java 层（TLS 已修好）把音频拉回来，
用明文 http 喂给 MediaPlayer，**Range 头原样透传**，所以进度条能拖。

各音源 Referer 不一样，`refererOf()` 按域名给：

| 域名含 | Referer |
|---|---|
| `bilibili` / `hdslb` | `https://www.bilibili.com/` |
| `126.net` / `music.163` | `https://music.163.com/` |
| `kuwo` | `https://www.kuwo.cn/` |

### 3.3 B 站搜索：路径必须是 wbi，老路径返回 0 条

这是最阴的一个坑：

```
/x/web-interface/search/type      → code=0, message="OK", data.result = []   ← 空的！
/x/web-interface/wbi/search/type  → code=0, 正常 20 条
```

签名完全正确、`code` 也是 0，就是没有数据。**只看 code 会误判成"搜不到这首歌"**。
签名算法本身没变（mixinKey 取 `wbi_img` 的 img/sub 拼起来按 64 位混淆表重排取前 32 位，
参数排序 + urlencode + md5），变的只是路径。

### 3.4 不知道盒子的 density，就别用 dp

T70L 逻辑分辨率 1280×800，但 `ro.sf.lcd_density` 从没记录过。
一旦 density ≠ 1.0，按 dp 写的界面会整体撑爆或缩成一小块。

做法：**全部尺寸按"屏宽/1280"缩放**。

```java
float U = Math.max(dm.widthPixels, dm.heightPixels) / 1280f;
int u(float v) { return Math.round(v * U); }
```

字号也走 `COMPLEX_UNIT_PX + u(字号)`，不交给 sp。
这样 1280 宽的屏上 1:1，别的分辨率等比缩放，永远不会跑版。

## 5. 语音点歌

沿用原设计，小智识别到「放 XXX」后发：

```bash
am start -a com.lm.music.PLAY -e q "晴天 周杰伦"
```

`MainActivity.handleIntent()` 收到后填搜索框、**主动 clearFocus 避免弹输入法**、搜完自动播第一条。
`launchMode=singleTask` + `onNewIntent` 保证连续点歌不会叠 Activity。

## 6. 踩坑清单（照抄别再踩）

1. **酷我直链假成功** —— 见 §2.2，正版歌返回 181KB 提示音，不同 rid 是同一个文件。
2. **B 站必须走 wbi 路径** —— 老路径 code=0 但 result 为空。
3. **4.4 TLS 双坑** —— 协议要强制、根证书要放行，缺一个都连不上。
4. **`android.util.LruCache` 不要贪多** —— 1GB 机器按 16 张封面封顶，再多会被系统杀。
5. **封面色用 RGB_565** —— 封面不需要 alpha，省一半内存。
6. **网络全在后台线程** —— 4.4 上主线程碰网络直接 `NetworkOnMainThreadException` 闪退。
7. **`playToken` 防止乱序** —— 快速连点 3 首时，慢的那个 resolve 回来不能覆盖当前播放。
8. **不要用 dp** —— 见 §3.4。
9. **`setDataSource(Context, Uri, Map)`** —— 4.4 有这个方法，能带 UA；不要用只接受 String 的重载（会拼错本地代理地址）。
10. **图标必须走 `mk_icon.py`** —— 桌面 1:1 画 BLOB，画布 220×280 / 实体 180×240 @(20,20) / 投影黑 `(26,25,33)`。
    这次的 `ic_music.png` 一开始是 192×192 的普通 launcher 图标，`check_icon.py` 直接判 FAIL，
    已换成 `launcher_standard/icons/music_v7.png`（PASS）。

## 7. 构建与部署

```bash
cd 核心资产/源码/11-听歌
bash build_music.sh          # → music.apk（约 54KB）
```

链路：`aapt` 打包资源 → `javac`（`-source 8 -target 8`，bootclasspath 用 `android-19.jar`）
→ `d8 --min-api 19` → `zipalign` → `apksigner`（`music.jks`，口令 `music123456`）。

```bash
adb connect 192.168.1.151:5555     # IP 会变，先 adb devices 确认
adb install -r music.apk
adb shell am start -n com.lm.music/.MainActivity
adb logcat -s MUSIC:*              # 看"屏幕 ... density=... → 缩放 ..."和搜索条数
```

⚠ 装包会触发桌面重建（`vulture.app.home`），装完要跑一次 `launcher_guard.sh` 收敛。

## 8. 后续可做

| 想做的 | 怎么做 |
|---|---|
| 退出界面继续放 | 抽一个前台 Service（4.4 用 `startForeground` + 通知），MediaPlayer 挪进去 |
| 歌词全覆盖 | 现在只有网易源带歌词；可对 B 站歌再拿歌名去网易搜一次，命中就取 LRC |
| 收藏/播放列表 | `SharedPreferences` 存 `Song.key()` 列表即可，不用数据库 |
| 下一首预取 | 播放中提前 resolve 下一首的直链（`audioUrl` 字段就是缓存），切歌秒开 |
| 音质再上调 | B 站 `fnval=16` 已取到 184k；要更高得登录（`SESSDATA`），风险自担 |
| 开机自启收音 | `BootReceiver` → 直接 `am start` 到听歌，配合小智唤醒即可语音点歌 |
